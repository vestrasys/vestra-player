# 实验工程规范

本规范用于六插件探针，不表示成品 API 已冻结。目标是可读、可替换、可验证的 Rust/Slint/TS 插件架构，不追求抽象数量或代码行数。

## 1. 职责与依赖

- Rust 宿主拥有播放会话、原生窗口、后端任务和系统资源；TS 插件拥有用户功能的策略与界面行为；Slint 表达原生界面。
- 每个插件只依赖公共 SDK、本插件代码和明确声明的第三方库。禁止跨插件引用、访问 host/runtime 私有代码、读取兄弟插件目录或直接通信。
- 插件文件系统/网络能力本身允许使用，但不得借此绕过公共播放器接口或独立性约束。可信 Node 插件不被宣称为权限沙箱。
- core 按注册的命令、能力、资源和来源路由，不包含六个探针名称的业务分支。插件资源有明确 owner，卸载只回收自己的资源。
- 工坊管理的是生成包的生命周期，不直接调用其他探针；Pi 和模型配置不成为 core 依赖。

## 2. 契约与状态

- 对外接口先写 usage、输入、输出、错误和清理语义，再实现。API 请求由 maintainer 记录批准/拒绝及理由，代码与契约同版本演进。
- 公共变更遵守[社区变更流程](../doc/plugin-probe-workflow.md#31-固定基线与受控迁移)：固定基线，先分类故障与能力缺口，兼容扩展回归旧消费者，破坏性调整有版本、迁移和切换证据；禁止静默改变已发布契约。
- TypeScript 开启 strict/noEmit 类型检查。外部输入使用 unknown 加运行时校验，禁止用 any 或双重断言绕过契约。
- manifest 和 RPC 校验必需字段、类型、有限数值、枚举、路径和不支持的字段。命令 ID 具名且可追踪；函数对象不经 IPC 传递。
- 权威状态来自宿主实际结果，界面不因点击成功就假定处理成功。异步结果绑定 session/revision，媒体切换后拒绝旧结果。
- API 不把每个效果实现扩成专名顶层方法。可以使用明确的处理参数/提供者契约，不提前实现无法验证的通用平台。
- 每个订阅、任务、子进程和文件句柄都有所有者及释放路径。停用和重复释放行为明确；资源关闭不依赖 UI 是否显示。

## 3. 异步、失败与安全边界

- 阻塞 I/O 和重处理不得长时间占用 UI 线程。媒体任务有进度、取消、最终状态及错误；取消不能虚报成功。
- 子进程用 argv 参数数组启动，不拼 shell 命令；临时目录独立创建，完成/失败/取消后清理。
- 请求有超时或终止策略；插件 EOF、崩溃、无效消息不会冒充正常完成。协议 stdout 与日志 stderr 分离。
- 字节数据注明格式、尺寸、采样率与时间单位；正常视频处理不将逐帧像素往返 TS。NES 等内容生产者的低分辨率实验传输需注明性能边界。
- 第一方 Rust 使用 forbid(unsafe_code)，通过依赖提供的安全接口或进程接入原生能力。不引入自己的 ABI 不安全代码。
- 生成插件先验证、试载，再替换已安装版本；失败保留旧版。限定 cwd 不等于 OS 沙箱。

## 4. 可读性与代码组织

- 函数围绕一个职责命名，区分解析、状态转换、I/O 和 UI 绑定；出现重复或真正独立职责时再抽模块。
- 不使用巨型 switch 把插件业务塞进宿主；协议方法分发可以 switch，但处理职责应可独立验证。
- 不为每个函数机械增加类、接口或包装层；避免隐式全局状态、晦涩缩写、随意类型断言和无理由的 lint 禁用。
- 用注释解释限制、所有权和非显然取舍，不重复代码。新源码顶部注明实验版本及最终 API 可能差异很大。
- 路径与错误信息可诊断，不硬编码开发机绝对路径。依赖精确锁定、注明许可证和用途，不检入下载模型、ROM 或构建缓存。
- 使用统一 formatter；Rust 使用 rustfmt/clippy，TS 使用项目选定的 formatter/typecheck。无法自动检查的规范由验收者给出具体代码证据。

## 5. 验证与证据

- 契约、协议、独立性、真实处理结果和生命周期分层验证。不能仅靠 mock ack 或成功字段证明功能实现。
- 样本和预期独立于被测实现：像素/PCM/有效媒体信息、真实字幕时间轴、ROM 执行和输入、生成包实际行为。
- 测试包含无能力、无媒体、错误参数、取消、媒体切换和卸载。断言可观察结果，不写镜像实现的测试。
- 六个插件单独加载与组合均需验证。公共 API 变更回归受影响消费者；最终同一代码状态接受独立验收。
- mock 仅替代外部模型/网络服务，保留真实 agent 编排、宿主、校验和处理路径；不调用付费模型。
- 测试跳过、平台不可用和未实听需明示；未执行不能标为已验收。最终报告分别列通过、失败、未覆盖。
