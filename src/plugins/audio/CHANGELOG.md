# Changelog

## 1.5.14

- Command states are player conditions (`plugin.when`) instead of functions that read `player.state`: the editing commands, Cycle Tracks, the channel modes and Load External Audio… are enabled by a condition, given again when the track list, the channel count or the source changes; the Audio Track items' check marks are `when.audioTrack`. The player keeps them current while the plugin is stopped too, and the plugin's log no longer lists these reads among a listener's reasons. Behaviour is unchanged.
- SDK 1.11 (events and triggers, Release B): `player.subscribe()` and `player.onChange()` are gone. What the state stream drove (the sync and channel follow, the Audio Track menu, auto-loading companion audio, the command states) now runs at `source.opening`, `source.ready`, `source.ended` and `audio.tracks.changed`, and at the flips of two conditions the player evaluates, `when.ready` and `when.open` (playing again after the end, closing after it). The channel count comes from `audio.reconfigured` (it replaces the second `stats()` read a second after a track change); the device list and the device in use from `audio.devices.changed` (it replaces the 5 s poll of the list and the unplug check on the stream). The panel follows the volume and mute with `player.stream()` only while it is on screen. Menus, the panel, the effects and the settings are unchanged; the plugin stays running for the whole run, as before: it follows the player with a stream from its activation, so its Audio tab compiles when the adjust column first shows and never when a file opens (ruling 2026-11-11). Test: it stays resident and names the stream as the reason. Who must change: nobody.

## 1.5.13

- The description's last line, starting with `→ `, says where to open the plugin; Store 0.3.1 shows it on the plugin's card, also before install. Description text and its translations only. Who must change: nobody.

## 1.5.12

- Manifest capabilities are gone (SDK 1.9.0, player 0.9.0): `capabilities` is removed from manifest.json. `activate()` now starts with `plugin.player.subscribe()` (was `events`) and then `await plugin.player.read()` (was `playback.read`), the calls that replace the two declarations that changed how it ran; the others need nothing. Behaviour is unchanged, except the ruled start-up order: the player's `window.state` read now comes before the state requests. Who must change: nobody.

## 1.5.11

- Audio Processing: Reset (`audio.reset`) is declared `destructive` (SDK 1.7.9): it puts the equalizer, Normalize and Crystalizer back to neutral at once and cannot be undone, so a built-in caller of `commands.run` (Ask Vestra) asks the user first. The palette, its key and the panel's Reset run it as before. No other command is marked: Audio Sync: Reset sets one value back to 0, and the presets, channel modes, toggles, tracks and devices are choices the user can make again. Who must change: nobody. Tests: `audio.reset` carries `destructive: true`, without a source and with tracks and devices, and no other command does.

- Menu sweep (menu redesign §4, mockup 04): Audio Track ▸ moves to order 301 (was 505), so it follows Play/Pause and precedes Subtitle Track ▸ (302) and Snapshot ▸ (420) in the same separator group; paths, ids and keys are unchanged. Who must change: nobody.

- Tools ▸ (SDK 1.7.12, user ruling 2026-11-11): Audio Track ▸ moves from the top level into the right-click menu's Tools ▸ (`["@tools", "Audio Track", …]`), first there, before Subtitle Track ▸ and Snapshot ▸; every track item and `audio.track.none` with its "Loading…" / "No Audio Tracks" text move with it. Ids, keys, order 301, group `domain` and the palette names (Audio Track: …) are unchanged. The store description says Tools ▸ Audio Track (six translations updated, machine-marked). Who must change: nobody. Tests: the menu paths in English and zh-Hans (工具 ▸ 音轨 ▸ …).

- **Audio panel** (menu redesign step 5, design of 2026-11-07): the Audio Workbench window becomes the **Audio** tab of the player's adjust column, the column of controls beside the video (player 0.7.6). One column, top to bottom: **Volume** (the player's volume and mute, as the bottom bar's), **Track** (the track list, Load… and "Same name", which loads same-name audio files automatically), **Output** (the device), **Channels** (Stereo / L / R / Mono / Swap, the full names in the tooltips), **Sync** (−50 / the delay / +50 / ↺; a click on the delay lets you type it, Enter applies, Escape cancels; Keep), **Equalizer** (on/off, preset, ten bands) and **Processing** (Normalize, Crystalizer with its strength), with **Reset** at the bottom. Each control's key shows beside it as a key cap and in its tooltip, always the key bound now (`plugin.commands.keys`): a key the user changed shows the new one, a cleared key none. The Volume row shows the player's own keys (Volume −, Volume +, Mute: `↓ ↑ M` by default; `commands.keys("host/…")`, SDK 1.6.16; an older player shows none). Below 300 px the Delay row leaves out its three caps (its tooltip still names them). The Equalizer, Effects and Output pages are gone; the panel scrolls when the window is short.
- **Audio…** (`audio.workbench`, was Audio Workbench…, default key **Alt+2**) opens the adjust column at the Audio tab, and closes it when that tab is already shown. It is a top-level item of the right-click menu, before Playlist (order 792, group `windows`).
- **The right-click menu keeps only** Open ▸ Load External Audio…, **Audio Track ▸** (now a top-level submenu at order 505, with the tracks and the greyed "No Audio Tracks" / "Loading…" item) and Audio…. The Audio ▸ submenu and Reset ▸ Audio Sync / Audio Processing are gone: every command keeps its id and default key and stays in the command palette under its category, with the panel as its home (`home: "audio.workbench"`), so the player shows Alt+2 under the tab. Palette names: Audio Sync: Reset (`?`) and Audio Processing: Reset (were Reset: Audio Sync and Reset: Audio Processing); Cycle Tracks and the channel modes keep their categories (Audio Track, Channels). The output devices are in the palette only; with no device list there is no "No Output Devices" item any more (the panel's drop-down says so).
- The panel's **Reset** resets the processing only, as Audio Processing: Reset: the equalizer (on, Flat), Normalize and Crystalizer (off, 3 dB). The sync has its own ↺ and the channels are a choice. Before, the window's Reset also zeroed the sync and set Stereo.
- **Ten equalizer bands** (31 Hz–16 kHz, ISO octave centres, ±6 dB), up from six (60 Hz–10 kHz). Saved gains of the six bands are spread over the ten (each new band takes the old curve's value at its frequency, on a logarithmic scale, the ends held), and the presets are the old ones spread the same way, so a saved preset is still that preset. `settings.json` is version 2: the ten gains are in `gains10`, and `gains` still holds the six-band curve read off the ten (the inverse of the spread), so going back to 1.5.10 plays a close curve instead of a flat one; when an older plugin changed `gains` since, its curve is read (spread) instead of the stale `gains10`. The old window's `tab` is no longer written. A band shows its gain while the pointer is on it; a double-click sets it to 0 dB.
- The panel's −50 / +50 step the sync like `>` and `<` without the on-screen message (the panel shows the value). Panel edits give no on-screen text, as the window's did.
- The volume slider and mute are always enabled (an empty device list does not mean no output: the player leaves mpv's `auto` device out). Only when the player refuses a volume or mute change (no audio output) do they grey out, with the player's reason in the tooltip; the next source, an output change or a device list read enables them again.
- Capabilities: `ui.mount` replaces `ui.window`. The plugin's name is **Audio** (was Audio Workbench).
- Who must change: nobody. Keys a user bound keep working (same ids). A user who used the Audio ▸ submenu finds its items in the Audio panel (Alt+2) or by name in the command palette (Ctrl+Shift+P).
- **Audio…** (`audio.workbench`, Alt+2) leaves the right-click menu and is in the command palette only (user ruling 2026-11-08): the right-click menu's player items **Adjustments and Effects** and **Sidebar** (named like the bottom-bar buttons) open the adjust column and the sidebar at their last tab instead. Title, category, id and key are unchanged. Who must change: nobody.

## 1.5.7

- The audio resets moved to the player's **Reset** menu (below Settings, player 0.6.3; user ruling 2026-11-01): **Reset ▸ Audio Sync** (was Audio ▸ Audio Sync ▸ Reset, `?`) and **Reset ▸ Audio Processing** (was Audio ▸ Reset). The window's Reset button is unchanged and still resets the whole window (sync and channels included).
- Requires player 0.6.3 (`minPlayerVersion`), whose menus have the Reset menu.

## 1.5.6

- A track with a long title no longer breaks the Audio Track menu. The menu item was cut to 60 characters, but the player takes at most 80 bytes per menu item: 60 Chinese or Japanese characters are 180 bytes, so the player refused the item, and while the plugin was starting this could stop the whole plugin. Now the label is cut by bytes so that it fits in every language of the plugin with " (external)" added (the widest is the Japanese and Chinese "（外部）", 12 bytes), on whole characters: an emoji sequence, a flag or an accented letter is kept or dropped as one (on a runtime without `Intl.Segmenter`, on whole code points). The text is at most 68 bytes; the language (up to 16 bytes) and codec (up to 24) are cut first on their own, so "[jpn] (aac)" is always kept, and the title gets the rest ("1. 日本語吹き替え版日本語吹き替え版… [jpn] (aac)"); before, the codec went first. The window's Track list and the "Audio track: …" on-screen message show the same shortened text as the menu. Who must change: nobody. What users see: every track shows up; long titles are a little shorter in the menu, the window's Track list and the on-screen message.
- Control characters in a track's title, language or codec (C0, DEL and also C1, U+0080–U+009F, such as NEL) become spaces and spaces at the ends are dropped, as the player requires of a menu item; a title of only controls and spaces counts as no title ("Track 2 (opus)"). Output device names get the same treatment; before, C1 controls were left in them.
- A saved output device id is checked as the player checks it: at most 512 UTF-8 bytes (it was 512 characters) and no control character, C1 included. An id the player would refuse is dropped at start (System Default) instead of being handed to the player.

- The Audio Workbench uses the player's shared form controls (`@vestra/widgets.slint`, player 0.6.0): the Track, Channels, Device and Keep sync drop-downs are the library `Choice`, the Equalizer, Normalize, Crystalizer and auto-load switches the library `Check` (panel style), and the Equalizer / Effects / Output strip the library `Tabs`. Who must change: nobody. What users see: the same window, sizes, labels and translations, with the shared look and keyboard use: a control reached with Tab shows a focus ring; a drop-down opens with Space, Enter, F4 or Alt+Down and its list is walked with the arrows, Page Up/Down and Home/End (Enter picks, Escape closes); a closed drop-down changes with Up/Down/Home/End; Space switches a check; Left/Right/Home/End move between the pages. A click still takes no focus, so the player's Space and arrow shortcuts keep working after clicking in the window. The drop-down lists stay inside the window; the Track list now shows at most 10 rows and scrolls beyond them (it used to show every track), the Device list still 7. Picking the track that is already selected no longer sends the switch again (it did nothing). The 4-preset menu and the equalizer band sliders are unchanged.
- The window's list labels (tracks, output devices and the device tip) now come from the plugin as text values, with the same words and translations as before. `minPlayerVersion` is 0.6.0.

## 1.5.4

- "Load audio files with the same name automatically" now leaves a file to the video whose name it matches more closely, as the Subtitles plugin does for same-name subtitle files (0.4.5). With `Movie.mkv` and `Movie.Extended.mkv` in one folder, `Movie.Extended.ac3` and `Movie.Extended.jpn.mka` load only with `Movie.Extended.mkv`; `Movie.ac3` and `Movie.jpn.mka` still load with `Movie.mkv`. Before, `Movie.mkv` also picked up the other video's audio, since its name starts with `Movie.`. Only files with a video extension in the same folder count as other videos (`.mkv`, `.mp4`, `.avi`, `.mov`, `.webm`, `.ts`, `.m2ts` and the like); names are compared case-insensitively, like the match itself.
- File names are compared in Unicode NFC as well as case-insensitively, as in the Subtitles plugin: macOS lists names in decomposed form (`Cafe` + combining accent), so `Café.ac3` was not found for an opened `Café.mkv` whose path came in composed form, or the other way round. Now it is.
- A file whose name is the video's name followed by two dots and the extension (`movie..ac3` for `movie.mkv`, an empty tag) is no longer loaded, as in the Subtitles plugin (`movie..srt`). `movie.ac3` and tagged names such as `movie.jpn.mka` load as before.
- Everything else about the scan is unchanged: off by default (mpv's `audio-file-auto` is `no` by default; when on, the match is mpv's `exact` plus any dotted tag), only local files, the folder of the video only, audio files sorted by name, at most 8, added without being selected.
