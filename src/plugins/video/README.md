# 画面调节（vestra.video）

功能：色彩（亮度、对比度、饱和度、色调、Gamma，四个预设与复位）、图像处理（高斯模糊、锐化、边缘锐化、3D / 渐进 / 瞬态降噪、去块、消色带、倍帧）、翻转与旋转、反交错（BWDIF：自动 / 总是使用 / 不使用，按帧或按场输出）、裁剪/拉伸到 4:3…2.35:1，作用于本插件自有的视频处理链 `picture`。链的顺序固定：反交错 → 裁剪/加边 → 翻转旋转 → 降噪 → 去块 → 消色带 → eq → 色调 → 锐化 → 边缘锐化 → 高斯模糊 → 倍帧（最长 14 个节点）。“启用画面效果”关闭时只清空本插件的处理链。

显示方式（宽高比、显示模式、帧位缩放平移）走显示层 `plugin.video.view()`，不改像素：截图、导出和处理链都不受影响。显示层只有一个拥有者；别的插件先占用时，「比例 ▶」「帧位 ▶」与窗口的这三行照常可操作，但屏幕提示“画面显示不可用：另一个插件正在控制画面显示”，窗口状态行显示“画面显示不可用”，那个插件释放后再操作一次（或点“重试”）即生效。

GPU 渲染选项（E16 HDR 色调映射、E17 像素着色器、E18 运动补偿）走 `plugin.video.render()`，不进处理链，“启用画面效果”与截图、导出都不涉及它们。软件渲染（无界面、`VESTRA_SOFTWARE_RENDER=1`、Windows、Linux）时 `render()` 为 `unsupported`：相关菜单项禁用、窗口控件置灰，原因“需要 GPU 渲染（当前为软件渲染）”；“着色器列表…”与“打开着色器文件夹”照常可用。另一个插件占着渲染选项时窗口状态行显示“渲染选项不可用”，用户操作时有屏幕提示。HDR 只作用于 `stats().video.transfer` 为 `pq` / `hlg` 的片源；已知是 SDR 时 OSD 加注“（当前片源不是 HDR）”，窗口小字接“当前片源不是 HDR”。着色器文件放在 `<dataDirectory>/shaders/`（“添加…”用文件对话框选文件并复制进来），编译失败时屏幕提示与状态行显示“着色器载入失败”（mpv 不报文件名）。倍帧与运动补偿互斥，打开一个时关掉另一个并提示。

倍帧（E18）：打开后先在不含倍帧的链上读 `player.stats().video.fps`（原帧率），再加 `frameBlend`，目标 min(原帧率 × 2, 60)；原帧率未知按 30 计（即 60），≥ 50 时不加节点，勾选仍为开，窗口里显示“当前帧率已足够”。每个来源、每种反交错设置各读一次（按场输出会让原帧率加倍）；没有画面时约 3 秒后放弃，直到换来源或重新勾选。打开后 `stats().video.fps` 读到的是输出帧率。

入口（右键菜单 `视频 ▶`）：`像素着色 ▶`（402，使用着色器 Shift+P、着色器列表…、打开着色器文件夹、重新载入着色器、`HDR 色调映射 ▶`（自动 / 关 / BT.2390 / Hable / Mobius / Reinhard / 裁剪，动态峰值检测）、HDR 设置…（打开窗口的「高级」页））；`反交错 ▶`（403，按序切换 Ctrl+I、三种模式、`输出 ▶`）；`比例 ▶`（404，保持宽高比 / 不保持宽高比 / 填满窗口（裁去多余）；依次切换比例 Shift+F6、默认（按来源）、4:3、16:9、16:10、1.85:1、2.35:1、自定义（x:y）、自定义比例…）；`裁剪/拉伸 ▶`（405，不使用 / 按比例拉伸 / 按比例裁剪、位置复位与上下左右移 5%）；`帧位 ▶`（406，帧位复位 Num5 / Alt+Backspace、全帧 + Num9 / Alt+Plus、全帧 - Num1 / Alt+-（×÷1.05，25%–400%）、偏移 → ← ↑ ↓ Ctrl+Num6/4/8/2 / Alt+方向键（每步 1%）、帧位居中 Ctrl+Num5；缩放与偏移按住重复）；`图像处理 ▶`（408，上下翻转 Ctrl+P、左右翻转 Ctrl+Z、高斯模糊 Ctrl+B、锐化 Ctrl+R、边缘锐化、去块 Ctrl+H、消色带、3D 降噪 Ctrl+N、渐进降噪、瞬态降噪 Ctrl+M、倍帧、运动补偿）；`图像旋转 ▶`（409，按序切换 Alt+K、不旋转 / 90° / 180° / 270°）；`画面调节…`（440）、`复位` Q（441）、亮度 W/E、对比度 R/T、饱和度 Y/U、色调 I/O（442–449，按住重复）。菜单与按键操作在视频左上角显示屏幕提示，例如“色调 +1% (+5%)”“锐化: 开”“倍帧: 开”“运动补偿: 开（已关闭倍帧）”“HDR 色调映射: BT.2390”“像素着色: 开 (2)”“图像旋转: 90°”“反交错: 自动”“裁剪/拉伸: 按 2.35:1 裁剪”“宽高比：自定义 - 21:9”“填满窗口”“帧位调整：增加尺寸 (110%)”“帧位调整：向左位移 (-3%, 0%)”。

自定义比例（`ui/aspect.slint`，240×98）：输入“宽:高”（21:9）或小数（2.39），范围 0.25–4；格式不对时框下提示“格式：16:9 或 2.39”，〔确定〕与回车无效；Esc /〔取消〕关闭。确定后菜单出现“自定义（21:9）”，并进入 Shift+F6 的切换序列。

窗口（`picture.slint`，301×245，四个页签，记住上次的页签）：「色彩」五行滑块与预设；「效果」六行“开关 + 强度 + 默认”（降噪行带 3D / 渐进 / 瞬态下拉）与第 7 行倍帧复选（旁边灰字“当前帧率已足够”）、运动补偿复选；「画面」翻转、旋转按钮与裁剪/拉伸下拉，宽高比下拉 +「…」（自定义比例）、显示下拉、缩放滑块（对数刻度 25%–400%，中点 100%，拖动时连续生效；“默认”= 帧位复位）；「高级」反交错模式与输出，HDR（色调映射下拉 + 目标亮度滑块 100–400 尼特，下一行灰字）、着色器（启用 + 个数 +〔列表…〕）。底部状态行：“启用画面效果”、失败时“画面处理失败”（悬停看原因）、“当前来源没有画面”“画面显示不可用”“着色器载入失败”“渲染选项不可用”或“渲染设置失败”与“重试”。

着色器列表（`ui/shaders.slint`，301×260）：已启用列表（按顺序执行，最多 16 个）与〔添加…〕〔移除〕〔上移〕〔下移〕〔清空〕，下面是文件夹里其它 `.glsl` / `.hook` 文件（双击加入），〔打开文件夹〕。

生效方式：eq、色调、高斯模糊拖动时连续生效；锐化、降噪、去块、消色带的强度滑块只在松开时提交（这些滤镜改参数要重建）。

设置：色彩、效果（含 `effects.frameBlend`）、反交错、裁剪/拉伸、宽高比与显示模式（`view.aspect`、`view.customAspect`、`view.fit`）、渲染选项（`render.toneMapping`、`targetPeak`、`peakDetect`、`shadersEnabled`、`shaders`（文件名）、`interpolation`）与页签跨文件、跨重启保留，存在 `<dataDirectory>/settings.json`（`plugin.storage.json`，`version: 1`；读坏的文件改名为 `settings.json.bad-<时间戳>`，未知版本按默认值启动且不覆盖原文件）。翻转、旋转与帧位（缩放、偏移）只属于当前来源，换来源时静默复位。

限制：没有就绪媒体时保留设置，媒体就绪后应用；按场输出或倍帧时若 5 秒内丢帧超过 5%，每个来源各提示一次（“反交错按场输出丢帧较多，可改为按帧”“倍帧丢帧较多，建议关闭”）。倍帧在 CPU 上处理（1080p 24 → 48 fps 约多 0.4 个核，4K 更多）。`peakDetect` 在 macOS（OpenGL 4.1，没有计算着色器）上不起作用；输出总是 SDR。运动补偿按主显示器刷新率重采样。工具窗口里不触发快捷键（宿主规则）。未做：按宽高比自动旋转（`stats()` 的宽高未经宿主的方向处理）。

开发：`npm run plugin -- check video`、`build video`（生成 `dist/`，版本取自 `manifest.json`）、`test video`。代码只用 `import type` 引用 SDK。
