# 音频工作台 API 请求

实验文档：此版本与最终产品 API 可能相差很大。

## AUDIO-001：有所有权的音频处理配置

状态：批准并调整为 v0.1 `ctx.effects.set({key,kind:'audio',filter})`，宿主提供 owner 作用域；类型安全参数封装留在插件内部。FFmpeg 表达式作为受信本地插件的后端 escape hatch，不是 shell。插件不创建子进程执行播放处理。

用户操作：加载任意有音轨媒体，通过原生 Slint 面板实时调节三段 EQ、响度规范化、人声增强、音频延迟；使用预设及复位。所有参数对后续媒体继续生效，直到复位或停用本插件。切换媒体不会偷偷修改参数。

现有 SDK 只有高斯滤镜，没有音频处理，不能完成此场景。

建议 usage（待批准，不是当前接口）：

```ts
await ctx.media.effects.set({
  audio: {
    equalizer: [
      { frequency: 100, gainDb: 3 },
      { frequency: 1000, gainDb: 0 },
      { frequency: 10000, gainDb: -2 },
    ],
    normalize: true,
    voiceEnhance: false,
    delayMs: 100,
  },
});
```

宿主按调用插件持有配置，参数更新原子化，失败保留之前成功配置；TS 不直接构造 FFmpeg 命令，也不读 PCM。宿主负责实际音频处理及媒体时钟同步。正值延后音频，负值提前，必须记录后端边界。停用只移除本插件贡献，不能清空其他效果。能力不支持或参数越界显式失败。

最小验收：真实子进程操作；在至少三频正弦混合样本上观测频段改变；低电平音频规范化后响度提高；人声增强有可测频谱变化；脉冲验证延迟；后续媒体继续采用参数；停用后移除自己的贡献且另一 owner 不变。

## AUDIO-002：多入口命令

状态：批准为 manifest.commands + ctx.onAction，复用现有动作语义。

用户可从音频菜单规范化开关、预设入口、面板调整共享一份状态。命令由插件注册和注销，不能向兄弟插件通信。命令与 UI 动作复用同一处理函数。
