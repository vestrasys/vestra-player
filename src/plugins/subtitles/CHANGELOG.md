# Changelog

## 0.4.11

- **Subtitles panel** (menu redesign step 6, proposal §3.2): one tab in the player's adjust column, beside the video (`plugin.panels.mount("adjust", "ui/panel.slint", { title: "Subtitles" })`), 317 px wide and usable from 280 px. It replaces the Subtitle Tuning and Adjust Sync windows (`ui/tune.slint`, `ui/sync.slint` are gone); Subtitle Settings stays a window, opened by the panel's **Font, Colour and Outline…**. Rows: **Show subtitles**; **Tracks**: Primary, Load… (Cancel while an operation runs), Reload, Secondary, its Position (Top / Above Main Subtitle); **Sync**: −step, the value, +step, reset, and **Previous / Next** line; **Style**: Size − value +, Position ↓ value ↑ reset (the value is mpv's `sub-pos`: 100% is the bottom edge, so the default 5% margin shows as 95%), B / Shadow / Box, Keep original ASS/SSA styles; **Reset** (the style and the sync, as Subtitle Settings' Reset All) beside a one-line status. Every label is one line, elided with its whole text in a tooltip; explanations are in tooltips; the elements stay and change only their values (nothing is created or destroyed per hover).
- **Keys beside the controls** (proposal §3.5): each control shows its command's key as a key cap (`KeyHint`) and in its tooltip (`ToolTipArea.keys`), read with `plugin.commands.keys`, so a key the user changes or clears shows at once; a command without a key shows none. Below 310 px the caps are left out and only the tooltips name the keys.
- **The sync value is typed in the panel**: a click on it opens a field; Enter applies, Esc keeps the old value, ↑/↓ step like − and +. The value is in **seconds**, as the panel shows it and as mpv's `sub-delay` takes it: `-1.25`, `+0,5 s`, `2`, or milliseconds with the unit (`250 ms`), within ±600 s. Before, the Adjust Sync window took whole milliseconds; a whole number above 60 without a unit is still applied in seconds, and the status line says so and names the millisecond form ("Sync set in seconds (250 s). For milliseconds, type 250 ms."). **Adjust Sync…** (`sync-input`, palette) now shows the panel with the value open for typing.
- **Subtitles…** (`tune`, was Subtitle Tuning…) is a top-level item of the right-click menu, default key **Alt+3**; it opens the adjust column at this panel, and closes the column when the panel is already in front (`panel.toggle()`); it is checked while the panel shows. The panel's position is “mpv's sub-pos”: 95% is the default 5% margin from the bottom.
- **Menus** (proposal §4): Subtitles ▸ and Reset ▸ Subtitle Position / Subtitle Sync are gone from the right-click menu. It keeps Open ▸ Open Subtitle… and Add Secondary Subtitle…, **Subtitle Track ▸** (Off and the tracks, now at the top level, order 302) and **Subtitles…** (order 793, group `windows`, beside Picture… 791, Audio… 792, Playback… 794; interaction-lead decision). Every other command keeps its id, its default key and its category and is in the command palette ("Subtitle Style: Bold", "Reset: Subtitle Sync"); Cycle, the secondary subtitle items, the style items, Sync Earlier / Later, Reload, Refresh, Subtitle Settings… and Original ASS/SSA Styles have titles instead of menu paths. Commands whose control is in the panel name it as their palette place (`home: "tune"`), Bold, Shadow, Opaque Box and Original ASS/SSA Styles included (they named Subtitle Settings before), and so do Previous Dialogue, Next Dialogue and Current Subtitle Start, which leave Playback ▸ Seek for the palette too (Home, End, Ctrl+Home unchanged; the host's and playback's Seek items are palette-only, so the Seek submenu is gone).
- New command **Remove External Subtitle** (`remove`, palette): the Subtitle Tuning window's Remove button, for the selected external subtitle this plugin loaded.
- The panel reads the subtitle state again every 1.5 s while it is on screen (the player has no subtitle event), as the windows did while open.
- New texts translated in all six languages and marked `x-machine`; the texts of the two windows that are gone were dropped from the catalogs; the description's second line now names Subtitles… (Alt+3).
- Who must change: nobody. Keys a user bound to any of these commands keep working (ids unchanged). What users see: the panel instead of two windows and a submenu; Subtitle Track ▸ and Subtitles… in the right-click menu. Requires player 0.7.6 (`minPlayerVersion`, unchanged), which has the adjust column, `commands.keys` and the key hint widgets; the manifest now also declares `ui.mount`.

## 0.4.7

- Track names in Subtitles ▸ Subtitle Track ▸ and Secondary Subtitle ▸ are always menu texts the player accepts. A title (with its language) is cut to 24 characters and 70 bytes, a language without a title to 16 characters and 32 bytes, by whole user-perceived characters (an emoji, emoji sequence or accented letter is kept or dropped as one; a surrogate pair is never split), and the edges are trimmed after the cut, so a title whose cut ends in a space no longer gives a menu text the player refuses. C1 control characters (U+0080–U+009F, NEL among them) become spaces like C0 controls and DEL; a title of controls only falls back to "Track N". With the fallback name, " · " and a duplicate's " (n)" (Japanese "（n）"), each track item stays within the player's 80 bytes in every language of the plugin.
- An embedded track without a title and without a track number is named "Track N" (its place in the list, with its language when it has one) in the menus, the on-screen messages and the Subtitle Tuning lists, instead of "Embedded " with a trailing space, which the player refused in the menu.
- A track titled like another track's duplicate name (for example "A (3)" next to two tracks titled "A") gets the next free number, so the menu items stay distinct. A track titled "Position" gets a number too ("Position (1)"), like "Off" and "Cycle" already did: Secondary Subtitle ▸ has a Position ▸ submenu, and the player refused a track item of the same name.
- Where the runtime has no `Intl.Segmenter`, names are cut by whole code points instead of user-perceived characters (a surrogate pair is still never split).

## 0.4.6

## 0.4.5

- Same-name subtitle files load automatically when a local video opens, as mpv does by default (`sub-auto=exact`); the player keeps mpv's own scan off (`sub-auto=no`) so that these files go through this plugin's reading: encoding detection, WebVTT/SAMI/MicroDVD conversion, Reload Subtitles and the automatic reload. A file matches when it is in the video's folder and its name is the video's name without the extension, optionally followed by a dot and a tag, then `.srt`, `.ass`, `.ssa`, `.vtt`, `.smi`, `.sami` or `.sub` (`movie.srt`, `movie.en.srt`, `movie.zh-Hans.ass`, `movie.en.forced.srt` for `movie.mkv`; not `movie2.srt` or `movie - trailer.srt`), compared case-insensitively (a file is still loaded once per exact path, so two files that differ only in case on a case-sensitive file system are two files). Unlike mpv, the tag can be any text (`movie.简体.srt`, `movie.chs&eng.ass`), and a file that names another video of the folder more closely is left to that video (`Movie.Extended.en.srt` goes with `Movie.Extended.mkv`, not with `Movie.mkv`).
- Order: the exact name first, then the others by name. At most 2 subtitle tracks per video are loaded this way, so you can still add your own and reload: the player keeps at most 4 tracks per plugin for each file, and Reload Subtitles loads the new track before removing the old one. If the player refuses a track anyway (its limit), loading stops there and the file is not given up: Refresh Subtitle Tracks loads it once there is room. The first one becomes the primary subtitle, as mpv prefers external files over the container's default track, unless a track was already chosen on this file through the menu, a key or Open Subtitle…, or another plugin's external track is shown. Nothing is shown on screen (mpv shows nothing either); the windows' status line says how many files were loaded, unless a newer status is there. A scan cut short by opening another file sets no status: "The media changed; the running operation was cancelled." is now shown only when a user operation or a style edit was cancelled, and the status line is cleared otherwise.
- Files that cannot be read, image subtitles (`.sub` VobSub), unknown formats, files over the size limits and files the player refuses as invalid are skipped and logged; a folder that cannot be listed loads nothing. Only local files: URLs, network sources and generated video (NES) are not scanned.
- Each file loads once per opened source: more player events on the same file load nothing again, while reopening it or moving to the next playlist item scans that file's folder anew. Refresh Subtitle Tracks also loads same-name files that appeared since the video opened (mpv's `rescan-external-files`), without switching away from a track chosen through this plugin; a file removed from the tracks is not loaded again for that source.
- Subtitle Settings… has "Load subtitle files with the same name automatically" (on by default, saved as `autoLoad` in `settings.json`); turning it on scans the video playing now.
