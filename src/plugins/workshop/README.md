# Vestra Player AI (experimental)

An AI assistant inside the player, based on [pi](https://github.com/earendil-works/pi). Use your own API key and chat with the model you choose; the AI can write Vestra plugins in the current chat's folder, type-check, test and pack them itself, and you can install the finished plugin or export it.

## How to use it

1. Choose "Tools ▸ Vestra Player AI…" in the right-click menu, or click the AI button at the right end of the bottom bar (left of the Plugin Store button).
2. The first time, click "Go to Settings" (or "⚙ Settings" in the sidebar), and in "Options ▸ Plugins ▸ Vestra Player AI":
   - choose a provider: all the providers pi supports that use an API key (Anthropic, OpenAI, Google, OpenRouter, DeepSeek, Mistral, Groq, xAI, MiniMax, Moonshot and others, pay-as-you-go), or "Custom · OpenAI format" / "Custom · Anthropic format" (enter a Base URL; works with Ollama, LM Studio or other compatible services);
   - paste the API key and click "Save"; each provider's key is saved separately;
   - choose a model. For a custom service, press Enter or click "Fetch Models" after entering the Base URL to ask the service for its models; if it cannot list them, enter the model ID directly.
   - "Thinking" sets how much a reasoning model thinks before it answers: Off, Low or Medium (the default; Low did not complete plugin tasks in validation). pi knows which of its providers' models reason; for a custom service only ids of clear reasoning models think (MiniMax M, DeepSeek R1, QwQ, o-series, GPT-5, Claude 4 and others; hybrid families such as Qwen3 do not by default), and "This model can think before it answers" changes that. Thinking tokens are billed by the provider like the answer.
3. Back in the AI window, type a message; Enter sends, Shift+Enter starts a new line. While a reply is being generated you can click "■ Stop".
4. While the AI works there is one activity line: it shows "Working…" at once and, once the AI uses its tools, the latest step ("Working… · Write main.ts ✓"); when the turn is over it reads how long the AI worked and how many steps it took ("Worked for 12 seconds · 3 steps"); click it (or Tab to it, then Space / Enter) to list the steps. The model's thinking is not shown. The reply below is the AI's answer.
5. On the left is the chat list: "+ New Chat" starts a new chat; click an item to switch to it. When you close the window and open it again, you return to the last chat. To delete a chat, click × on it (shown on the hovered or open chat), "Delete Chat" at the top of the open one, or press Ctrl+Shift+Backspace (⌘⇧⌫ on macOS); after a confirmation its messages and its plugin projects (`work/`, packed files in `dist/`) are deleted. Files you exported elsewhere and plugins installed from it stay.
6. "Open Folder" opens the current chat's working folder.
7. Enter your GitHub user name under "Plugin author" on the settings page: plugins the AI creates get the id `<user name>.<name>` (the official plugin repository requires the id prefix to be the GitHub user or organization that owns the source repository). Without it the id is `local.<name>`, which is only for use on your own machine; change the id before publishing. `vestra.` is reserved for official plugins and cannot be used.

## Ask Vestra

The command palette (Ctrl+Shift+P, or the search button on the bottom bar) has "Ask Vestra" as its first row. Type what you want ("mute and 1.25× speed", "rotate the picture", "a bit slower") and press Enter on that row: the palette closes, the model you chose in the settings plans the steps and the player carries them out; the on-screen line says what was done, with **Undo**. When what you type names a command ("pause"), the cursor starts on that command instead, so Enter runs it as before; ↑ goes to Ask Vestra.

- It runs the commands of the command palette (the player's and the plugins'), as if you picked them there, and sets any playback speed from 0.25× to 4×; up to 8 steps per request. Picture effects come later.
- The player asks before a command that deletes or clears something, closes or quits (Run / Don't Run), and before every command of a plugin that is not built in. Don't Run stops the whole request; what ran before stays. A disabled command stops the request with its reason, and a command that opens a window ends it: you are in that window then.
- The first request to a provider (for a custom service: to its Base URL) asks once whether to send it there. Sent: what you typed, the player's command list (names, menus, keys and whether each command is on or available) and the playback state (playing or paused, position, duration, speed). Never sent: the file name or a folder of your computer, and no command made from your data (Recently Played, track, chapter and bookmark titles, audio devices; a plugin from elsewhere's commands that look like a file name or a path). Each request costs a model call on your provider account. If you agreed to the first version, which sent no command list, you are asked again.
- While it works, the palette's first row reads "Vestra is working…"; Enter on it, **Stop** on the on-screen line or "Vestra: Stop" stops it. A new request stops the one running.
- "Vestra: Undo Last Request" (or **Undo** on the on-screen line) restores the speed from before the request; the last 10 requests can be undone one by one until the player quits. If you changed the speed yourself since, Undo leaves it alone and says so. Commands cannot be undone in this version: the on-screen line names them ("Cannot be undone: Rotate: 90°").
- Without a model set up the row says "Set up a model first" and Enter opens the settings.
- The row is offered only by the built-in plugin; a development load of the plugin runs without it.

## Writing plugins

When you ask the AI to write a plugin, it first reads the plugin SDK reference (read-only, inside the plugin package) and then uses these tools; the status line shows their display names:

| Tool | Status line | What it does |
| --- | --- | --- |
| `scaffold_plugin` | Create plugin | Creates a project in the layout of the official plugin repository: manifest.json, main.ts, ui/, tests/, README, CHANGELOG |
| `typecheck` | Type check | Strict type check (with the SDK types that come with the player); errors include file, line and error code. With SDK 1.5.26 or later it also lists every SDK call whose capability manifest.json does not declare (file, line, capability), which the player would refuse at run time; the AI adds the capability or drops the call |
| `test` | Run tests | Runs `tests/*.test.ts` in a separate restricted Node process: it can only read the plugin folder and only write a temporary folder, with no network and no child processes; on failure it returns the assertion messages and what the tests printed |
| `check` | Check | id, dependencies, manifest, types, build, then the player's own package checks on the packed plugin (`packages.validateArchive`: every Slint file compiled, as at install); a Slint error comes back to the AI with the player's diagnostics |
| `pack` | Pack | Creates `dist/<id>-<version>.vxp` |
| `install_plugin` | Install | The player validates it (including Slint), asks for confirmation in a dialog, then installs it (only when you ask) |

The AI is done only when type check, tests and check all pass. Every tool has a time limit and an output limit; clicking "■ Stop" cancels the running tool. When the `vestra-plugin` command line fails without its usual report, the tool result carries its exit code and the end of its error output, never an empty failure.

When the chat has a plugin project, a plugin card appears above the input box once the AI has finished its reply (while it is still working, the card stays hidden; it comes back with the latest state when the reply ends):

- "Install": installs it into the player (the source is recorded as the AI workshop); if a plugin with the same id came from elsewhere, you are asked first whether to replace it. Installing again after a change upgrades the plugin in place and keeps its data. A plugin you disabled stays disabled when it is installed again (players after 0.6.3, as in VS Code): the card and the AI say so, and only you enable it again, in the Plugin Store; the AI is told not to. To remove it, use Uninstall… in the Plugin Manager. If, after installing, the plugin's shortcuts are taken by the player or another plugin (the player ignores those keys), both the card and the AI are told; for this the plugin reads the shortcut table (`bindings.manage`, read only; it changes no keys).
- "Export .vxp": packs the plugin and saves a copy you can share.
- "Export Source .zip": the complete plugin project, ready to become your own GitHub repository: README, CHANGELOG, tests, tsconfig, a package.json with the SDK dependency, a GitHub Actions workflow (check, test, pack), VS Code settings that use the project's own TypeScript (so the SDK's editor plugin, listed in tsconfig.json, marks an API call whose capability manifest.json does not declare and offers to add it), and a LICENSE placeholder to replace; without node_modules and dist.
- "Open Folder": the plugin project's folder.

## Notes

- **How keys are stored**: only in the system keychain (macOS) or Credential Manager (Windows), never in any file, log or chat history. The cost of calling the model is charged to your provider account.
- **Reading the key**: it is read only when the AI window opens, and kept in memory after the first read. The system may show a permission dialog (common after a player update); if you deny it or reading fails, the top of the window says "Cannot read the key from the keychain; save it again in the settings", and everything else keeps working.
- **What the AI can do**: it can only read and write the current chat's working folder (`read`, `write`, `edit`, `ls`, `find`, `grep`, `delete`; `delete` only removes files or empty folders, for cleaning up debug files), it reads the plugin SDK documentation with `docs` (a tree of short pages by path, from `/` down, like `go doc`) and `docs_search` (by words), and it can read the SDK package itself for exact types (read-only, short paths `sdk/…`, for example `sdk/dist/plugin/testing/index.d.ts`, or the API types in `sdk/dist/plugin/types.d.ts` and, from SDK 1.6.21, `sdk/dist/plugin/types/`; models often copy long absolute paths wrongly). It cannot run commands, cannot access other files, and cannot use symbolic links or file names starting with ".". The AI runs in a separate restricted process. The plugin tools are run by the plugin process with fixed arguments. Tests and type checks (typecheck) run in Node's permission mode (`--permission`): they can only read the plugin project, the SDK and the SDK copy in the data directory, only write a temporary folder, and have no network; tests cannot start child processes; type checks can, but only to start `tsc`, which inherits the same limits. check and pack do not run in permission mode yet (the `fs.cp` the SDK command line uses to copy files reads every parent directory of the target in permission mode).
- **Where chats are stored**: in `sessions/<chat>/` in the plugin data directory: `meta.json`, pi's chat history (`.jsonl`), the working folder `work/` (one `work/<id>/` per plugin) and the pack results `dist/`. `node_modules/` in the data directory is a copy of the plugin SDK, used for type checks and tests.
- Only one chat generates at a time.
- Text the AI writes before a tool call ("I'll start by reading…") is a progress note: it shows while it is written, then gives way, as it is not the reply (a turn that ends without a reply shows its last note as the reply). The chat history keeps it as written.
- The text of every message can be selected with the mouse and copied (right-click: Copy, Select All; Ctrl+C / ⌘C), and every message, yours and the AI's, has "Copy" under it for the whole message.
- Files in the working folder are limited to 1 MB each; a search (grep) names the files it skipped for that reason.
- AI replies are shown as Markdown (headings, lists, tables, code blocks and so on); code blocks have "Copy" in the top right corner. The text of a reply can be selected; a paragraph with links keeps its links clickable and is copied with right-click ▸ Copy (the addresses included). Web images in replies are not downloaded; only their alt text is shown. Very long chats show only the most recent messages; the full history is in the session folder.
- The provider list has only pay-as-you-go APIs; subscription plans such as coding plans or Token Plans are not in the list; to use one, connect it with "Custom · OpenAI format" or "Custom · Anthropic format".
- Needs Vestra Player 0.6.8 or later (selectable reply text). The interface texts are written in English; the Simplified Chinese translation is in `locales/zh-Hans.po` (`vestra-plugin i18n extract` updates `locales/messages.pot`).
- The plugin SDK (`vendor/@vestra-player/sdk`, including the `vestra-plugin` command line), TypeScript and `@types/node` come with the plugin, at the same SDK version the player uses (`npm run vendor:sdk` updates them, `tests/vendor-sdk.mjs`). The documentation the AI reads is the SDK's own tree (`@vestra-player/sdk/docs`: `dist/docs.js` and `dist/docs-tree.json.gz`, SDK 1.5.50 or later), loaded from the vendored copy, never from a `node_modules` folder.
- Evaluation: `tests/eval/` has 6 fixed tasks; `npm run eval` runs them with a real model (this costs money on your provider account; run it by hand only after changing the prompt or the tools), see the notes at the top of `tests/eval/run.mjs`.
- Licenses of third-party components are in `licenses/` (shipped with the plugin package); the source of the pi logo is in `licenses/pi-logo/NOTICE.md`; the licenses of the SDK, TypeScript, `@types/node` and `undici-types` shipped with the plugin are in their own folders under `vendor/` (`LICENSE`, `LICENSE.txt`, `ThirdPartyNoticeText.txt`).
