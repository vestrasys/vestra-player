# 插件管理（vestra.plugins）

依据：doc/product/feature-requirements.md「插件管理（`plugins`）」J07；裁决 R-G1–R-G3、R-H10。列表、停用、启用、卸载、回退全部经 `plugin.packages`（写操作需要 `plugins.manage`），确认用 `dialogs.confirm`，打开数据目录用 `system.openPath`。插件只是界面，不和别的插件通信。

## 菜单与快捷键

| 菜单路径 | order | group | 默认绑定 |

| 设置 ▶ 插件管理… | 836 | settings-plugins | （无） |

## 窗口（`manager.ts`、`ui/plugins.slint`）

600×420（最小 520×320）。

- 列表（按 id 排序，跟随 `packages.onChange`）：插件 id 自适应 / 版本 70（开发加载无版本时「开发」）/ 来源 70（已安装、开发加载、试载）/ 状态 70（运行中、启动中、已停用、启动失败、已停止）/ 数据 60，行高 18；已停用行暗色，启动失败的状态列用强调色。
- 详情（6 行可滚动，标签 80）：失败原因、说明（开发加载 / 试载 / 自身）、上一版本、包目录、数据目录、能力（每项附中文说明）。路径过长时省略，悬停显示全文。
- 按钮：`停用`/`启用`、`重新加载`、`回退到上一版本`、`卸载…`，右侧 `打开数据目录`、`关闭`。

## 行为

- 停用：先确认（说明效果立即撤销、媒体继续播放；已安装的重启后仍停用，开发加载只在本次运行内）；`setEnabled(id, false)`，OSD「已停用 id」。启用不确认。
- 重新加载：`setEnabled(false)` 再 `setEnabled(true)`；已停用时不可用（用启用）。
- 卸载：只对已安装插件；确认框（破坏性）带复选框「同时删除它的设置与数据」（默认不勾选）→ `uninstall(id, { removeData })`，跟随 `PackageChange` 直到结束；OSD「已卸载 id」。
- 回退：有上一版本的已安装插件；`packages.rollback(id)`，消息行跟随状态（准备中 / 激活中 / 已完成 / 失败…），失败显示 `message`。
- 自身那一行：停用、卸载、重新加载、回退都禁用，悬停「插件管理不能停用自身」（核心同样拒绝，`invalid`）。回退自身会让本插件在操作中途重启，所以也禁用（需求只要求停用与卸载）。
- 开发加载：可停用、启用，不能卸载、回退；试载：只显示，不提供操作（`打开数据目录` 也禁用：试载的数据目录是临时的）。
- 操作进行中或状态为「启动中」时该插件的按钮全部禁用（「正在更新」）。
- 打开数据目录：`<数据根>/<id>`，数据根 = `dirname(plugin.dataDirectory)`（参考 §3.4）；目录不存在时（插件从未保存过数据，核心不预先创建停用插件的目录）提示「数据目录不存在」。
- 数据大小：窗口打开时在插件进程里逐个统计（只读文件名与大小，不读内容，不跟随链接），每个目录最多 2 秒，超时或目录不存在显示「—」；列表中出现新插件时补算。
- 错误码对应：`invalid` 自身、`unsupported` 开发加载 / 试载、`missing` 已不存在、`busy` 正在安装或回退。

插件自己不保存任何设置（停用集合由核心写进安装库）。

## 开发

在 `src/` 下：`npm run plugin -- check|build|test plugins/plugins`。
