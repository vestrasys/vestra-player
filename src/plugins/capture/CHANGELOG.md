# Changelog

## 1.0.14

- Wording left over from the clip tasks, now about snapshots: Show Last Capture in Folder and Copy Last Snapshot before any snapshot was saved say "No snapshot saved yet." (was "This task has no output file yet."); a sixth snapshot while five are saving says "Five snapshots are still being saved. Please wait." (was "One export is running and four are queued."); a failed write says "Could not write the image file" (was "Export failed"); "This frame cannot be encoded" (was "This media"); "The frame is past the end of the media." ## 1.0.13

- **Snapshot only** (user ruling 2026-11-09): clip export leaves the built-in plugin and becomes a store plugin; this plugin keeps saving, saving as and copying the current frame, the rendered frame and the video frame, bursts, their settings, keys and the right-click Snapshot ▸. Who must change: users who export clips install the store plugin. What users see: no Capture sidebar tab and no Export commands.
- Gone with the clips: Export Clip…, Export Clip Range (Ctrl+Shift+E), Export Last N Seconds (Ctrl+Shift+R), Set Clip Start / End, Export Tasks…, Capture… (Alt+S) and the Capture tab (`ui/tab.slint`, `ui/parts.slint`, `clip.ts`, `results.ts`, `seams.ts`): the clip page (Fast / Precise, encoder settings, estimates, the keyframe probe), the clip range on the seek bar, the Results list (running and finished captures with Cancel, Retry, Open, Copy, Remove, thumbnails, `results.json`), the progress card and the Last N s length.
- **Options ▸ Video ▸ Snapshot** (`ui/settings.slint`), opened by **Snapshot Settings…** (command palette only, as before; Snapshot ▸ now has three items: Save Current Frame, Copy Current Frame, Burst): the folder, save beside the media, format and JPEG quality, Include video effects, the burst's count, interval, effects and subtitles, and the frame and burst file-name templates with their variable chips.
- **Burst** (Ctrl+G, was Burst…) now takes the burst at once from the frame shown at the press, with the settings' count and interval, as PotPlayer's consecutive capture does; the typed start time is gone. Its message has Show in Folder (no Show in Tab).
- Show Last Capture in Folder and Copy Last Snapshot act on the newest capture of this session (no list is kept across restarts). A failed capture is said on screen and not kept for a retry.
- Palette `home`: the format and folder commands point at Snapshot Settings…; the frame commands have none (they lived in the tab).
- Manifest: `ui.settings` added; `ui.mount`, `timeline.marks` and `events` removed; punchline and description say what is left; tag `export` removed. Translations: three new texts (machine in de, es, fr, ja and ko, marked `x-machine`), every text of the tab and the clips removed from the catalogs.

## 1.0.12

- Menu sweep (menu redesign §4): the Snapshot ▸ submenu moves from Video ▸ to the top level of the right-click menu, after Audio Track ▸ and Subtitle Track ▸ in the same separator group (its first item's group is `domain`, was `capture-quick`); the five items, their order and the separator before Capture… are unchanged. Who must change: nobody.

- **Capture tab** (the Snapshots & Clips design of 2026-11-07, approved): one sidebar tab beside Playlist and Chapters replaces the Burst, Export Clip, Export Tasks and Snapshot Settings windows (`ui/tab.slint`; `burst.slint`, `clip.slint`, `tasks.slint`, `settings.slint` and `error.slint` are gone). A jump strip leads to its four sections: **Snapshot** (Save, Save As, Copy of the source and the rendered frame with their key caps, Subtitles, Format and JPEG quality, the Burst row), **Clip** (Start / End typed as `1:02:03.450` or seconds, Now, Use A-B range, Last N s, audio, effects, subtitles, an estimate, the file name, Export into the snapshot folder and Export As…), **Results** (a ListView of running, queued, failed and finished captures with Cancel, Retry, Open, Copy, Show in Folder and Remove; Open Snapshot Folder, Clear Finished) and **Settings** (folder, save beside the media, file-name templates, the Last N s length). A progress card stays at the top while an export runs. Who must change: nobody. What users see: the tab instead of four windows; every feature is still there (design §6).
- **Pages, not one long column** (user rulings after the GUI check of 2026-11-07): the tab, titled **Capture** so that it fits the default sidebar width (its menu entry is **Capture…** to match), has four sub-tabs that are real pages: **Snapshot** (Save and Copy only), **Clip** (Fast / Precise with an ⓘ tip that explains them, Start and End with Now, Use A-B range, Last N s, a closed **Advanced** with audio, quality, video effects and burned-in subtitles, Export and Export As…; a running export's progress at the top of this page), **Results** (the list, which fills the page) and **Settings** (folder, image format and quality, Include video effects for snapshots, Burst, file-name templates, Last N s length). The pages are always there and shown with `visible`, so switching creates nothing; the page shown last is remembered; Export Clip… shows Clip, Export Tasks… Results, Snapshot Settings… and Burst… (Ctrl+G) Settings. A capture that finishes while Results is not in front counts on its sub-tab instead of adding a line to the page shown. No text in the tab wraps: each is one line, elided, with the whole text in its tooltip (a wrapped line was laid out one line tall and overlapped the rows below it), and no explanation boxes: the Fast keyframe shows on the small timeline (a mark and its time, how much earlier), the file name and estimate in the Export button's tooltip.
- **Save and Copy as mpv's `screenshot`** (user ruling): Save / Copy Current Frame (Ctrl+E, Ctrl+C, the Snapshot page) take the frame at the source's size with the subtitles shown, and with the video effects when Settings says so; subtitles the player cannot draw into a frame are left out rather than failing, and the message says so ("Frame saved without subtitles as …", "Frame copied without subtitles: …"). While subtitles are shown the frame also has the video effects of plugins that have any: the player draws subtitles only into the frame with effects (a host request to separate them is to follow). The source frame alone is **Save Video Frame Only** and **Copy Video Frame Only** (`capture.saveVideo`, `capture.copyVideo`, palette); Save / Copy Rendered Frame are unchanged. Before, Ctrl+E saved the source frame without subtitles.
- Right-click Snapshot ▸ keeps five items: Save Current Frame, Copy Current Frame, Burst…, Export Clip… and **Capture…** (new, Alt+S, shows or hides the tab). Every other command stays, with its id and keys, in the command palette. Burst… (Ctrl+G) opens the tab with its burst row open and is checked while it shows; Export Clip… opens the tab at its Clip section (or scrolls there) and never exports; a range the user has not typed is set to the position → +10 s (within the last 10 s of the media, its last 10 s); Export Tasks… and Snapshot Settings… jump to Results and Settings. The palette's places (`home`) are now Snapshots & Clips…, and Snapshot Settings… for Snapshot Folder….
- New commands: **Export Clip Range** (`capture.clipExport`, Ctrl+Shift+E, the Export button's key: exports the tab's range into the snapshot folder, says a failure on screen, and opens the Clip section while there is no range), **Export Last N Seconds** (`capture.last30`, Ctrl+Shift+R; N is 10, 30, 60 or 120, 30 by default, chosen in Settings, and the title says it; a range the user typed stays in the fields, empty fields show the range exported), **Set Clip Start** and **Set Clip End** (`capture.clipStart`, `capture.clipEnd`, no default keys). Default keys checked against the built-in command table of the design.
- **File-name templates** for frames (`{name}_{pos}`), clips (`{name}_{start}-{end}`) and burst folders (`Capture-{date} {time}`), with `{n}` too. The frame default is the old name; a clip now also states its end; a burst folder is named by date and time instead of `Capture-` and a random suffix. Illegal characters become `_`, an empty template uses the default, existing files and folders are never reused (`(n)` is added). Windows device names (`CON`, `NUL`, `COM1`, `aux.png` …) get a `_` after the part before the first dot; a name is at most 168 characters (the source's name gives way first), so with its extension and `(n)` it stays within 180.
- **Results are kept across restarts**: the last twenty finished captures (`results.json` in the data directory), with a thumbnail made by the bundled ffmpeg (one thread) into `thumbs/`; a moved or deleted file says so. Running tasks and failed input stay in the session, as before.
- The tab reads the player's state only while it is on screen (a passive read of `Panel.state`, no layout listener), so a background tab keeps nothing running (lazy activation). The typed range and burst fields survive standby in session storage.
- **Fast and Precise** (SDK 1.6.10, player 0.7.6; `seams.ts` holds one small function per host request):
  - **Fast** (the default): a stream copy (`format: "copy"`, container `auto`: MP4 when the codecs fit, else MKV, and the file gets that extension), lossless and about as fast as the disk. The Clip section shows where it will really start: the keyframes come from the bundled ffprobe (packet flags only, no decoding), on the player's clock (a file whose timestamps start later, such as MPEG-TS, is shifted by its start time), and the note, the small timeline and the file name use the keyframe. Effects and burned-in subtitles are Precise only. A file the player cannot copy fails with "Fast cut is not possible for this file. Use Precise." and a **Use Precise** button.
  - **Precise**: a re-encode from the exact frame with the tab's settings (`ExportEncoding`): **Same as source** (the source video's average bitrate), **High quality** (CRF 18, the encoding clips always had) or **Small file** (CRF 26, at most 1080p), and **Advanced**: resolution, frame rate, quality number, speed, audio bitrate; any change reads Custom. Encoded with `threads: "auto"` (the cores the player can spare, at most half, at below-normal priority; one thread was about 10 times slower than real time on 4K). A source whose bitrate the player cannot tell asks for another quality.
  - **The range written** (`outcome.start` / `end`): the Results row states where the file really starts and ends.
  - **Progress** (`JobState.progress`): the progress card and the running row show the percentage and the time left.
  - **The clip on the seek bar** (`TimelineLayer.setRanges`, a `selection` range titled Clip) while the tab shows: what the file will hold (a Fast cut from its keyframe); it goes when the tab goes to the background. Manifest: `timeline.marks`.
  - **Buttons in the "saved" message** (`osd.show` actions): **Show in Folder** and, for a frame, **Copy**, for a clip or burst, **Show in Tab** (Results). They run two new palette commands that act on the newest result, **Show Last Capture in Folder** (`capture.revealLast`) and **Copy Last Snapshot** (`capture.copyLast`), and Export Tasks….
  - Use A-B range still needs the A-B loop switched on (design R7 has no API yet; `clip.ts` `abRange`).
- Times are typed as `1:02:03.450`, `02:03.450` or seconds, also `.5` and `5.`. Units (`s`, `MB`, `×`, `fps`, `kb/s`) are translated texts, not built in code. The tab's key (Alt+S) shows at the end of its sub-tab strip where it fits, and is left out where it does not.
- Translations: every new text in all six languages (machine in de, es, fr, ja and ko, marked `x-machine`); the texts of the removed windows are gone from the catalogs.
- Manifest: `ui.mount` and `timeline.marks` added, `ui.window` removed. Requires player 0.7.6 (`minPlayerVersion`, unchanged) with SDK 1.6.10: `commands.keys`, `KeyHint`, `ToolTipArea.keys`, timeline ranges, OSD actions, stream copies, encoder settings and job progress.

## 1.0.8

- Export Tasks: the list no longer lags while a video plays. With SDK 1.5.45's precise invalidation, state changed outside SDK-invoked code is drawn only at the next update (up to about a second later while playing), and three task-row changes happened after an `await`: the history trim (beyond 20 tasks, each further old task is removed after the previous one's snapshot is released), a task's first job state once the export call returns (`Preparing` becoming `Exporting`), and a burst frame's output once its job finishes (`Exporting · 3/10` counting up). All three now call `plugin.update()`. Who must change: nobody. What users see: the rows change at once.

## 1.0.7

- The Burst, Export Clip and Snapshot Settings dialogs use the player library's `Choice` and `Check` (`@vestra/widgets.slint`) instead of std-widgets' `ComboBox` (3) and `CheckBox` (7), so every drop-down and check box in the player has one look. What users see: Vestra-style drop-downs (21px, the list below with at most 10 rows, arrow keys / Home / End change the choice, Space / Enter / F4 open it) and check boxes (13px accent box, a label that wraps instead of widening the dialog); a control reached with Tab draws a 1px accent focus ring, and clicking one no longer takes the keyboard focus from the player. The Format choice reports a pick only when it changes. Who must change: nobody; the dialogs' properties and callbacks (`format-index`, `audio-index`, `choose-format(int)`, `set-beside-media(bool)`, `set-screen-subtitles(bool)`) are unchanged.

## 1.0.5

- Lazy activation (player 0.5.21, SDK 1.5.40): the plugin no longer keeps running while idle. Who must change: nobody. What users see: nothing new; the Snapshot items are greyed with "No frame to capture" (translated as before) until a frame can be captured, and the Burst and Export Clip dialogs show what they did. Under `VESTRA_LAZY=1` the player may now stop the plugin while nothing uses it and start it again on the next capture.
- Save / Save As / Copy Current Frame and Save / Save As / Copy Rendered Frame (and Ctrl+E, Ctrl+C, Ctrl+Alt+E, Ctrl+Alt+C) are enabled by a condition the player evaluates, `when.can("snapshot").and(when.phase("ready", "ended"), when.stream.not())`, the same rule as `usable` in model.ts, with the fixed reason "No frame to capture" the player shows only while the condition is false. Before, their `enabled` and `reason` were functions of `plugin.player.state`, which kept the plugin listening to every playback update.
- The Burst and Export Clip dialogs read the player's state (the folder shown, whether a frame can be captured or exported, the audio tracks) only while open: those values are bound in a child scope made when the dialog opens and disposed when the user closes it (or when it fails to open), and read afresh at the next opening. Before, the closed dialogs' bindings read `plugin.player.state` from activation on. Their other values (busy, progress, status, format) stay bound as before.
- Requires player 0.5.21 (`minPlayerVersion`), whose menus evaluate `plugin.when` conditions.

## 1.0.4

- Save Current Frame, Save Rendered Frame, Copy Current Frame, Copy Rendered Frame and a "current frame" Burst capture the frame shown when the key (or Start) was pressed, like mpv's `screenshot` and PotPlayer. Before, the player froze its current frame only after the snapshot folder was checked and the state read again, up to about 100 ms (several frames) later while playing. The position read at the press is now sent as the capture time, as Save As already did; this costs nothing, since every snapshot is decoded by the export worker anyway. Paused, the frame is the same as before.
- The saved file is named by the time the player reports for the captured frame, which is also the frame the export writes, like mpv's `screenshot-template` `%P`. Before, Save Current / Rendered Frame named the file by the position read at the press while the picture was the later frame (`movie_00.04.400.png` holding the frame at 00:00:04.467). Bursts name each file by its own sample time, as before; Copy has no name; Export Clip uses the times in its dialog.
