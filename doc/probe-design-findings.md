验收者记录了 95 个实现/测试文件与宿主 binary 的运行前后哈希；协调者另行核对这些文件、binary 以及基线的 74 项文件/契约哈希，均与实际工作树匹配。代码尚未提交，不把旧 git HEAD 当作本次实现修订。

证据已保留在[本轮产物](probe-evidence/2026-10-17/README.md)，包含完整日志、摘要、源码指纹、GUI 观测及八张关键截图。环境为 macOS aarch64、Node 25.9.0、Rust 1.92.0、FFmpeg-full 9.0.2、Slint 1.18.1；JSNES 2.1.0、Pi Agent Core / Pi AI 1.3.0 使用各插件独立锁文件。

## 实验要回答的问题

六个插件不是为了提前复刻完整参考播放器，而是用不同消费者检验 core 与插件的边界：多入口共享状态、处理链所有权、会话隔离、异步任务、外部音视频来源，以及插件生成和安装。流程模拟社区，公共 API 通过请求、基线、迁移与真实消费者回归演进。

## 已有证据支持的方向

| 需求                 | 当前分工                                                            | 实验观察与限制                                                                                                                                                      |
| -------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 画面、音频参数       | TS 提供参数策略和预设；Rust/FFmpeg 处理实际数据                     | 不需把普通视频逐帧传入 TS。真实 PNG/PCM 测试比仅确认 RPC 成功更有说服力。当前 filter expression 直接绑定 FFmpeg，不是跨后端处理器规范。                             |
| 字幕及翻译           | 插件解析、选择与翻译策略；宿主拥有会话与合成资源                    | 异步结果必须绑定 session/revision；seek 后的绝对媒体时间是宿主责任，不能让插件反复修正时间轴。mock 只替代翻译服务。                                                 |
| 截图、片段和连续任务 | 插件组织用户流程；宿主拥有任务、处理快照、进度和取消                | 只有复制参数还不够：引用文件也属于处理输入。必须冻结其内容和生命周期，不能因另一个插件改写或卸载而改变既有任务。                                                    |
| NES                  | 插件内成熟 JSNES 核心执行 ROM；宿主接收 RGB/PCM、输入和权威来源状态 | 实际 ROM、非零 PCM、按键和存档恢复已有证据。低分辨率 base64 进程通信不是高分辨率视频的性能方案。                                                                    |
| 原生界面             | 插件提供 Slint 源码和行为；Rust 编译组合并管理窗口                  | 不引入 TS 控件布局框架。未知界面首次接入仍需运行时编译与窗口替换；已接入面板条件显示，不增加编译/窗口次数。六探针、生成插件、字幕、菜单回调和输入均经真实窗口验证。 |
| 插件工坊             | 可选插件接入真实 Pi 编排和 mock 模型；宿主提供通用校验/管理事务     | 模型、BYOK 或生成业务没有进入 core。真实 Pi 循环收到真实 TS2322 后修复；生成包实际安装并执行计数动作，失败/取消/回退和卸载工坊后继续运行均通过。                    |

## 独立验收改变了哪些判断

现有五个探针最初的 25 项测试全部通过，但独立审查仍复现了卸载临时目录泄漏、显式非法采样率被当作缺省、普通插件被生成包管理接口移除，以及字幕文件改写使不可变处理快照改变。另发现 GUI 安装路径与 headless 参数校验存在差异。问题编号及复现保留在审查报告，不用旧通过记录覆盖。

这些反例说明，公共 API 的生命周期、输入校验和资源所有权必须由宿主完整实现；插件作者的正常路径测试无法代替独立消费者测试。卸载需要允许 disposer 的公共清理请求完成，不能在宿主线程阻塞等待进程退出，又要求插件等待宿主回复。

文件资源问题促成显式版本迁移：宿主在效果注册时取得受管资源副本，由效果、快照与任务持有，最后引用释放后删除。通过通用资源声明实现，不猜测任意 FFmpeg 表达式中的文件路径，也不按字幕插件名称分支。具体 API 与迁移证据由 maintainer 的[请求台账](../src/sdk/api-requests.md)及[基线登记](../src/sdk/baselines/README.md)维护。probe-0.2 保留失败记录；probe-0.3 通过本轮验收。未声明的外部资源不在内容冻结保证内，不能将可信 FFmpeg 表达式的 escape hatch 宣称为自动识别所有依赖的通用框架。

统一检查又发现新卸载流程破坏旧消费者退出，以及字幕测试依赖启动目录。前者应修复 runtime，保留旧测试对正常退出的要求；后者应修复测试路径，而不是只挑选能通过的启动位置。能力新增、破坏性契约迁移与实现回归必须分别记录，不能每遇到一个失败就要求插件修改 API 调用。

## 本轮不能外推的结论

- 当前播放实验使用 FFmpeg/ffplay，**没有接入 mpv**。本轮证据不能证明更换播放引擎后无需修改后端。
- 当前文件视频使用 FFmpeg 处理链；NES 等外部 RGB/PCM 来源直接呈现，未统一经过相同画面/音频效果链。本轮 N1/N2 不要求该能力，不能据此宣称所有来源已经统一处理。
- Node 插件是可信本地代码，进程分离、工作目录限制和静态边界检查都不是安全沙箱。
- 原生窗口测试使用真实 Slint 菜单/global 回调，不等于物理鼠标键盘自动化；离线 PCM 结果不等于设备实听；macOS 证据不等于跨平台验证。
- mock Pi 模型用于可复现生成与修复，不证明真实供应商协议、开放式需求理解或生产 BYOK 已完成。
- 工坊的候选目录、进程级安装事务与回退不等于生产插件商店；跨播放器重启的安装清单、依赖安装、更新分发和迁移持久化尚未验证。
- 本轮有限 use case 通过也不代表最佳或最终架构。性能、通用渲染管线、平台设备、发布和长期兼容策略仍需后续独立验证。

## 对下一轮架构设计的含义

核心不能只转发插件消息：它需要完整负责会话、资源归属、处理输入、任务取消、安装事务和进程生命周期。插件可以保有策略、第三方库、文件 I/O 和原生 Slint UI，而无需彼此依赖。当前公共能力已支持六类差异很大的消费者，没有把六个插件业务名称加入核心。

社区模拟中的版本纪律同样是架构的一部分。本轮仅让确实受破坏性变更影响的字幕调用和测试 provider 迁移，其他插件继续使用兼容子集；运行时回归由维护者修复，没有让所有作者反复更改调用来掩盖故障。后续可以继续以新的独立插件检验边界；本轮已达到既定完成条件，不因可能存在更优设计而继续无限重构。
