# P1 共同契约候选有限独立复核

2026-10-17，审查者 `rebuild_bootstrap_review`。本次仅阅读本轮 P1、R1/R2、八插件方案及其新 UI 可行性说明；未读旧实现、未修改 src 或作者方案、未构建或操作 GUI。结论是候选设计复核，不是实现验收或共同版本发布。

## 结论

**P1 六组设施覆盖八方案，可开始阶段 D 的必要公共能力实证；优先 M2 实时处理风险试验，再推进 M1。共同基线尚未就绪发布。** 未发现需要推翻候选方向的原则冲突、范围删减或过大架构矛盾。现有可运行契约仍是 `vestra.experimental/0.1`；P1 不构成产品实现任务授权。

P1 保留 Rust 公共设施/所有权、TS 策略、Slint 原生呈现的边界，没有按插件身份提供业务分支。稳定 owner 排序使用 manifest ID 是通用排序，不是业务特判。有限挂载、有限 descriptor、单 producer 和包事务都有实际使用场景，未扩成停靠平台、任意滤镜语言、持久全局请求数据库或通用工作流引擎。

## 覆盖关系

| 消费方案 | 必要公共设施与边界 |
| --- | --- |
| 基础播放 | 第1组来源状态/控制意图/CAS/操作查询、真实 mute；第2组底栏/命令/输入域/dialog。宿主不接管打开策略或播放栏业务 |
| 播放列表 | 第1组真实终因、来源/意图条件与去重操作；第2组 sidebar/model/多文件选择。队列、稳定 rowId、导航锚和自动下一项策略仍在插件 |
| 画面调节 | 第3组 typed eq/gblur owner 资源、完整更新/失败保旧、暂停重绘；第4组只读快照。高斯、预设和连续拖动场景均保留 |
| 音频工作台 | 第3组 EQ/增强/规范化、owner 偏移与实时更新；第4组 processed 音频链/preroll。没有把离线音频当实时连续性证明 |
| 字幕工作台 | 第3组 SRT 内容/选择 CAS/唯一呈现层/条件恢复，第4组字体及内容快照；第1/2组来源隔离与原生列表。翻译和取消策略仍由插件 worker 执行 |
| 截图/导出 | 第4组独立 source lease、不可变完整快照、有限任务/取消/无覆盖发布；第2组 Save/目录及任务 model。raw/processed、连拍和片段均保留 |
| NES | 第5组有界二进制 AV、消费音频时钟、epoch、主画布输入/强制撤销；第1/2组来源条件及原生交互。核心/ROM/存档序列化归插件；C2 已收窄为新路径无覆盖保存及预热后无持续增长趋势 |
| Pi 工坊 | 第6组真实校验/trial/activation-ready/持久安装与回退，第2组本地菜单、窗口、dialog。真实 Pi 工具循环和诊断修复仍属交付范围，仅模型 mock；不把 load 进程冒充安装成功 |

不同内部音频设施可用成熟 safe 适配，但对用户仍须统一 volume/mute、来源切换不重叠/无残音；这是实现验收边界，不要求第一方 unsafe 或强行共用同一设备对象。

## 发布前窄修，不阻止必要实验

1. **preroll 文档统一。** 初读时 capture C2 与 R2 仍保留3秒候选；收尾复读已确认 capture C2 正文/usage 改为 P1/audio C2 的源0至导出起点重算。B1/R2及验收矩阵余处由协调者统一，不能让两个消费者实现不同历史。此项不要求克隆实时 DSP 状态，不承诺实时逐样本相等。
2. **视频确认层级统一。** 初读发现 video C2 VD-02 的“呈现revision”及“先准备再原子交换”旧措辞；收尾检索已无这两处文字。共同发布应继续按 P1：applied 是完整后端接受并确认，失败恢复上份有效配置；真实像素是验收证据，无新增 visible fence 或未经证实的 mpv 原子 swap 承诺。完整预设失败保旧仍必须满足，不能用措辞修正免掉它。
3. **来源条件需在 usage 收敛时统一。** 部分方案仍用 session/expectedGeneration 简写，P1 已增加 intentVersion/播放周期以覆盖 restart、pause 等同 generation 意图竞争。最终 SDK 示例须用正式条件类型，NES 候选准备、列表 auto-next、基础播放控制及任务启动不能各自定义不同 CAS。这里不批准任何现有伪代码签名。
4. **任务与包事务的 owner 死亡规则要写成一张最终状态表。** 未提交媒体任务随 owner 取消；已经 commit 的安装不随工坊死亡撤销；管理接管中的安装在 prepare/activate/commit 各点由谁收敛、取消何时 tooLate，最终实现与示例须一致。现有 P1 方向足够继续实证，无需为此新增工作流平台。

以上是共同发布门槛和文档收敛事项，不是要求回到从零设计 API，也不要求现在实现八插件。

## 最小实证优先级

1. **先做 M2 的技术风险切片。** 在锁定本机后端上逐项验证 eq/gblur、EQ/treble/dynaudnorm 所需运行时参数和开关；5秒连续提交及最终值、暂停视频重绘、真实像素/PCM、动态历史与 A/V 同步、有效链→故意失败→旧链恢复、两个 owner 撤一留一。限制可回滚的故障注入，不对“手册有 command”作实现成功推论。不支持关键参数或连续性失败时先记录具体证据研究成熟 safe 路线，不能每事件重开播放器或静默换算法。
2. **随后 M1 的原生 UI 与来源竞态，两条都不可只做 headless。** 两个独立消费者提供栏/sidebar，加一个已准备工具；菜单驻留10秒、真实 dialog、首次候选失败保旧，观察实际 draw/音频。另一切片用真实后端来源关联验证快 open、旧 error、ended→restart/manual open 与旧 auto-next，CAS stale 无副作用，timeout 可查原 operation。不得把 currentSession 重命名为 generation 冒充关联。
3. **M3 先一份完整 processed 产物。** 同时冻结视频+字幕/字体+音频处理/偏移，接受后切源/改参/撤 owner，检查真实可解码产物；再补 raw 基准、源0 preroll、取消及已有文件 hash 不变。此切片证明 descriptor 能同时映射实时和离线，而非只证明 snapshot ID 不变。
4. **M4 各做一个最小真实消费者。** 单 producer 真 ROM/PCM→pause→输入 release→切普通文件；计数器离线 JS+Slint 真校验→坏 activate 保旧→升级/回退及工坊停用后独立运行。不要求先完成全套产品 UI 才暴露公共设施风险。

这些是能力实证优先级，未改变工作流：维护者先补可运行公共设施和 SDK usage，集中对齐设计/API/宿主/能力发现与迁移清单，独立核验必要证据，再由 root 发布共同基线并统一分发产品实现。API 签名、锁版依赖或尚无产品证据本身不应阻止必要实验；但不能因此提前宣布共同基线或降低最终验收范围。
