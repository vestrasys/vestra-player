# 当前十产品生产独立性审查与最终验收缺口（2026-10-19）

结论：在下列固定哈希的当前可读生产入口及其静态依赖中，未发现跨产品 import、读取另一产品实现、专用产品通信或新增产品专用 Host IO。当前 Rust Host 未发现 unsafe 实现或按 NES、站点、某 UI 插件身份进行业务特判。此结论是静态范围结论，不是十产品功能验收通过。

本轮只读，未运行产品、作者测试、Host、Cargo、GUI、音频或付费模型；没有修改产品/SDK/Host。生产入口按 manifest/marker 区分：workshop 是包根 main.js；NES、Bilibili 是包根 manifest 指向 dist/main.js，其余本次选择 dist manifest。未用 freeze-ready 的“ready”字段代替功能证据。

独立脚本使用 TypeScript AST 遍历静态 import/export、字面量 import()/require()/__require()，递归检查本地依赖与 jsnes 的 ESM 导出分支，并对 realpath 做产品目录边界检查（已消除 macOS /tmp→/private/tmp 等价路径假阳性）。除下述 TypeScript 自身可选探测外，未发现缺失模块、越出所属产品目录或非字面量加载。完整边与哈希见 static-independence-results.json。Node标准库和本包第三方依赖不算跨产品依赖。

Workshop vendor TypeScript 的 source-map-support 是 try/catch 包裹的可选探测（vendor/typescript/lib/typescript.js:8374–8378），本包未解析到该模块；这不是已证实加载失败。该编译器还保留通用 require(baseDir,moduleName) 能力（:8394–8399）；本业务调用固定离线编译器和 transpileModule，未发现借此加载另一产品实现。AST 静态审查无法排除任意生成字符串路径，不能当形式化隔离证明。工坊所生成候选用本包 SDK 类型，不 import 其它产品。

两站 resolver 的 id 和 hosts 位于各自可信 JS 中。Host 的 source_resolvers.rs 只按声明 schemes/hosts、owner、resolver id 路由，并校验通用媒体 descriptor；没有硬编码 YouTube/Bilibili 域名。播放列表仅向公共 source.submit 提交原 URL，属于公共能力协作，不是产品私有通信。NES 的 jsnes、ROM判断与逐帧运行位于可信 JS；Rust producer 是通用 AV/epoch/input 协议。捕获的 mkdtemp、文件查验及 shell:false 系统打开、字幕的 fs/crypto、工坊的 fs/process 都是允许的可信 TS IO，未要求为这些业务新增专用 Host 接口。

## Rust 当前实现

本次 src/host/src 的 40 个 .rs 均实际可读；没有因 iCloud 目录存在就当作读到源码。与 maintainer-source 当前备份比较时，main.rs、ui_values.rs 已更新，因此最终静态结果以实际 src/host/src 为准，不用较旧备份覆盖它们。全部模块 SHA256 记录于结果 JSON；main.rs 声明的模块均有对应可读文件。

main.rs:1 为 #![forbid(unsafe_code)]；扫描未发现 unsafe block/fn/impl/trait/extern 实现。该范围覆盖本轮 Host crate 自有代码，不声称第三方 crate 内部也没有 unsafe。搜索插件/站点名与 manifest.id 的结果仅有通用身份校验、去重、试载命名、卸载及包身份一致性；未发现具体产品 id 决定业务分支。main.rs/source_backend.rs 的字符串“capture”是通用输入捕获事件，不是截图产品特判；processing 的“audio/video”是通用处理stage。
