# 本轮组件与阶段登记

本表登记工作范围，不是插件交互设计，也不发布插件实现任务。所有组件先完成统一规范下的方案和集中审查，再依据共同基线实现。当前仅 API maintainer 获得阶段 A 编码任务。

| 组件 | 职责与必要场景 | 当前状态 |
| --- | --- | --- |
| 公共宿主与 SDK | Rust/TS 通信、实际 libmpv 播放、Slint 原生显示、插件生命周期、错误和清理；参数更新不重建播放会话 | rebuild_api 实现阶段 A |
| 基础播放插件 | 读取媒体、播放/暂停、跳转、常驻播放栏；工具界面显示时仍可操作 | 待统一交互规范及插件设计 |
| 播放列表插件 | 添加多文件、列表导航和播放、显示/隐藏；不借用基础播放插件私有逻辑 | 待设计 |
| 画面调节插件 | 明暗、对比、颜色、预设、复位及高斯处理；参数和效果共存、所有权及撤销 | 待设计 |
| 音频工作台插件 | 均衡器、音频延迟、规范化/增强、预设和复位；连续操作不打断画面 | 待设计 |
| 字幕工作台插件 | 读取字幕、轨道、样式、同步、异步翻译及取消；旧结果不覆盖新会话 | 待设计 |
| 截图/导出插件 | 原始/处理后截图、字幕选项、连拍与片段导出、进度、取消、不可变来源和参数 | 待设计 |
| NES 插件 | 合法 ROM、真实模拟核心、输入、暂停、存档、独立来源及音频资源生命周期 | 待设计 |
| Pi 插件工坊 | 需求→真实 agent 工具循环→生成→真实校验→诊断修复→安装→回退；仅模型调用 mock | 待设计 |

六探针中画面调节包含高斯，不预定再为高斯建立独立插件。最终模块划分若因设计调整，需说明责任和场景如何完整保留，不能借合并/拆分减少功能。

当前不包含 DLSS、付费模型调用、生产分发包及未经验证的 GPU/HDR 性能承诺。正式终端用户安装插件不需要 Rust 编译器；阶段 A 源码开发需要工具链，与成品插件安装不同。

产品交互负责人由 root 暂任；本轮新建交互设计 agent 将负责具体规范和跨插件一致性。各插件作者、文件所有权、设计版本及基线将在任务实际分发时登记，不能将“待分配”当作已实现。
