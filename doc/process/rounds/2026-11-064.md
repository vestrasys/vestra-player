## Findings

- **First-use compile never armed the 0.6.3 shader guard** (no frame drawn); the watchdog took a 50 s+ ArtCNN compile for a hang. Fixed by the watchdog rule, the shader cache and the 0.6.4 guard rule (a GPU failure after a shader change and before a frame with it finished on the GPU, while a video is open).
- **Old process panics in wgpu after a device loss** (`util/device.rs:72`, "Failed to get mapped range for buffer created with mapped_at_creation", main thread), seen with `VESTRA_TEST_REMOVE_DEVICE` on both 0.6.3 and 0.6.4: the process ends abnormally instead of logging `exit: restarting`, so plugins read `host-lost`, not `quit`. Pre-existing; open.
- F4 in the 2026-10 Windows render record was the reverse of the brief: the code already used `MonitorFromWindow`; the fix moves the extra pixel off a neighbouring monitor. F6 had two readings (clock reopen on a new monitor, host.log rotation); both were done.
- mpv v0.40.0 `video.c`: `//!WHEN` hooks are skipped without compiling while false; options are re-read at the start of a render call. Whether `change-list` has synced `m_config_cache` when it returns is unchecked.
