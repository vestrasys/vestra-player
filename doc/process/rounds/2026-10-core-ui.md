# 本轮任务：核心界面与输入能力变更（第一步，自上而下）

分支：`rebuild/core-ui`（自 `rebuild/sdk-v2` 136de92）。流程按[社区工作流](../community-workflow.md) §5（自上而下）。每个 agent 开工前读完：本文、社区工作流、[界面整改文档](../../product/ui-alignment.md) §2、§3、§6、§8、§9、§10，以及与自己相关的小节。

## 1. 目标

把[界面整改文档](../../product/ui-alignment.md) §10 列出的核心改动一轮做完：C1–C11 与 C14（C12、C13 已定不做）。下游插件**配合更新到新接口，不改交互**；交互改版是第二步（整改文档 §11，自下而上）。

用户已确定的决定见整改文档 §1：D1 PotPlayer 配色、D2 保留独立工具窗口、D3 截图直接保存（第二步做）、D4 删除 Commands 按钮且不做 macOS 菜单栏、D5 播放信息插件、D6 播放列表可分离浮动。

## 2. 原则

- **核心不臃肿**：每项能力只做最小接口；被新机制取代的旧接口和特殊处理在本轮删除，**不保留兼容层**（迁移期间可以短暂并存，P4 删除）。不预做没有使用者的能力（用户改绑界面、菜单布局文件、控制面板容器都不做）。
- **插件之间不通信**：需要多个插件共享的东西做成核心能力（如 C6 播放序列、C7 侧栏状态），插件只和核心打交道。
- **行为不变**（对下游插件）：菜单项的位置、名称、顺序、启用条件，快捷键，窗口与按钮，在迁移前后一致。宿主自己的界面变化（C1、C2、菜单样式）是本轮预期的变化。

## 6. 迁移者任务（P3）

### 6.1 开工前阅读

本文、社区工作流 §5.2、`doc/architecture/core-ui-design.md`（尤其迁移写法一节）、`doc/plugins/reference.md`、参考迁移（`src/plugins/playback/`、`src/plugins/playlist/` 的新版本）、自己插件的代码和测试。

### 6.2 要做的事

1. 把插件改到新写法，**行为不变**：菜单项位置、名称、顺序、启用条件不变；快捷键不变（`shortcut` → 等价的 `bindings`）；窗口、按钮、文字不变。
2. 被删除或改名的接口换成新写法。
3. 不采用整改文档中的交互改版（菜单移位、新快捷键、屏幕提示、视觉改动），那是第二步。
4. 不新增功能、不提新能力请求。新接口表达不了现有行为时，按社区工作流 §5.2 报「迁移阻塞」。

### 6.3 完成条件

- `npm run plugin -- check|build|test <名字>` 全部通过。
- 插件源码中没有 `shortcut:`，没有使用 §5「删除」列中的旧接口。
- 菜单快照与 P0 的 `menus-before.json` 中本插件的部分一致（路径、标题、快捷键）；协调者用同一脚本复核。
