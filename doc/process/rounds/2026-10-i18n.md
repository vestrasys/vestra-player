# 2026-10 轮：多语言

开始于 2026-10-24。**本文是这一轮的唯一进度来源。**

## 用户裁决（2026-10-24）

- 所有界面文字以**英文为原文**，中文改为翻译。
- 界面语言：英文原文 + 6 种翻译——简体中文、日本語、한국어、Deutsch、Français、Español，共 7 种。**繁体中文取消**（用户：港台用户不多，可以看英文；新加坡用户用简体）。
- 选项里可以选择界面语言，默认「跟随系统」；系统语言不在支持范围内时用英文。
- 不为每种语言各写一份 Slint；用 Slint 的 `@tr` 和 gettext 词典，TS 文字走 SDK 提供的同一套词典。插件作者自己决定提供哪几种语言。

- 2026-10-24 维护者方案的三个问题：
  - 繁体取消，回退问题不复存在；
  - 中日韩字形如果在阶段 0 核实确实用错，**允许**按语言指定系统自带的界面字体，只限 ja、ko；这是对 10-22「不指定字体」裁决的破例；
  - 实时切换采用方案 B：用 Slint 内部库 i-slint-core 的外部 Translator，封装在 `src/host/src/i18n/slint_bridge.rs` 一个文件里，升级清单加一项，同时向 Slint 上游请求公开 API；失效时退回方案 A，即换语言时重建窗口。

## 修订（2026-10-24，用户裁决，取代下文方案中冲突的部分）

- **切换语言只在下次启动时生效**，取消实时切换。选项里改了语言，提示「重启后生效」。
  - 宿主在加载插件时，用 Slint 公开的 file loader 把 `@tr("原文")` 里的原文替换成当前语言的译文，Slint 只负责格式化。
  - 因此**不再依赖 i-slint-core 内部 API**（上一条「用内部库」的裁决作废）。复数只区分 1 与非 1。
- **插件做多语言时 TS 里不写任何翻译代码**：
  1. 声明类文字（菜单标题和路径、设置页标题、面板/页签名、窗口标题、manifest 的 name/description）填英文原文，由宿主用该插件的词典翻译；
  2. 窗口里的文字都写在 Slint 里，用 `@tr`，TS 只传数据；
  3. OSD、对话框等 TS 直接发出的文字，API 用「模板 + 参数」，例如 `osd.show("Speed {}×", [rate])`，宿主按模板查词典。
  - 规则：用户看得到的句子不在 TS 里拼接，`vestra-plugin check` 尽量检查出来。
- **SDK**：只有只读的 `plugin.i18n.locale`；没有 `t()`、`onChange` 或翻译引用。
- **流程**：按 §5 自上而下，分两轮派活，本轮并发上限放宽到 8：
  - 第 1 轮：维护者完成宿主、SDK、迁移指南，并亲自迁移 preferences 作为参考 → 协调者审查、真机验证、合并、发版；
  - 第 2 轮：所有插件作者一次完成迁移，包括顺手写 `zh-Hans.po`；5 个翻译 agent（ja、ko、de、fr、es）在拿到 `.pot` 后同时开工；独立验收者负责审查，协调者负责真机截图。

## 维护者方案要点（上一版）（2026-10-24，全文待阶段 0 写入 doc/architecture/i18n.md）

- **Slint**：当前构建里 `@tr` 只做格式化。gettext 只支持 unix，bundled 翻译解释器不支持，所以采用 i-slint-core 的 `tr` feature 加自定义 Translator，用 `update_all_translations()` 实时切换。通过 file loader 给每个插件的 `@tr` 加上 `<manifest-id>\u{4}` 前缀作为上下文，从而按插件区分词典。
- **SDK**：`plugin.i18n.locale/preference/onChange/t/t.n/mark/set`；每个插件的 `locales/messages.pot`、`<lang>.po` 在构建时编译成 JSON；新增 `vestra-plugin i18n extract|check`，check 只警告；manifest 的 name、description 也可翻译。
- **菜单**：宿主用插件自己的词典翻译 title、path、页面标题；合并菜单用英文 key；共用子菜单的英文 key 登记在 menus.md；旧中文锚点作为别名继续可用。
- **设置**：`ui_state.appearance.language`；系统语言用 sys-locale 检测；语言变化时广播 `i18n.changed`；preferences 插件提供语言入口，语言名一律用各自的本名显示。
- **译文**：每种语言一个翻译 agent，另一个 agent 审校；机翻条目标 `x-machine`；简体中文由用户抽查。
- **规模**：约 1,590 条中文字面量要改写成英文原文。
- **分阶段**：
  - 阶段 0：基础设施，加试点插件 preferences 和 playlist；
  - 阶段 1：其余插件、宿主字符串、译文；
  - 阶段 2：文档与商店。

- 2026-10-24 用户：**不发 0.4.3**。多语言全部完成后与今天的 Windows 修复一起发 **0.5.0**；Actions 额度到那时再开。
- 2026-10-24 用户在 Windows（未装中文语言包）上看到中文显示为方框。**0.5.0 必须修**：界面字体在 Windows 上要回退到系统 CJK 字体（文件名、字幕、歌曲名等仍会出现中文）；没有可用字体时给出明确提示。归维护者。

### audio（R2-audio-1）：命令标题带模板参数

- **请求插件 / 代码位置**：`src/plugins/audio/main.ts` `rebuildTracks`（「声音 ▶ 音轨 ▶ <音轨>」动态菜单项），`model.ts` `trackTitle`。
- **用户操作与预期结果**：中文用户打开「声音 ▶ 音轨」，没有标题和语言的音轨显示「音轨 2 (opus)」，外部音轨显示「3. movie.ac3 (ac3)（外部）」，与迁移前相同。
- **现有 API 为什么做不到**：命令的 `title` / `path` 段只能是原文字符串，宿主按原文整句查词典。音轨标题由数据（序号、编码）和文字（「音轨 {}」「（外部）」）组成，没有可以查到的固定原文；SDK 1.5.9 里没有 `t()`，TS 也不得拼接句子。最小复现：`plugin.commands.add({ id: "t", path: ["@audio", "Audio Track", "Track 2 (opus)"], run })`，`startPlugin(..., { locale: "zh-Hans" })` 下 `display.path[2]` 仍是 `"Track 2 (opus)"`，即使 `zh-Hans.po` 里有 `msgid "Track {} ({})"`。窗口和 OSD 已改为模板（`@tr("Track {} ({})", …)`、`osd.show("Audio track: Track {} ({})", [n, codec])`），只有菜单做不到。
- **希望的用法**（与 `osd.show` 一致，可选字段，不破坏现有契约）：

  ```ts
  plugin.commands.add({
    id: `audio.track.${t.id}`,
    path: ["@audio", "Audio Track", "Track {} ({})"],
    args: [n, codec], // 只作用于最后一段（标题）；extract 照常收集模板
    run,
  });
  ```

- **状态与资源归谁；失败、能力缺失时**：宿主在注册时用插件词典翻译模板再填参数（与 OSD 相同规则，参数不翻译）；旧播放器忽略 `args`，显示未填的模板——所以需要 `minPlayerVersion` 再升一级，或者 SDK 在旧播放器上先格式化英文。
- **是否破坏现有契约**：否，新增可选字段。可能也会用到的插件：带「（外部）」「（无记录）」之类后缀的动态菜单（subtitles、history 等，由各自作者确认）。
- **最小验收场景**：`locale: "zh-Hans"` 下无标题音轨的 `display.path` 为 `["声音", "音轨", "音轨 2 (opus)"]`，外部音轨为 `"3. movie.ac3 (ac3)（外部）"`。
- **本轮的临时做法**：菜单里这两种情况显示英文（`Track 2 (opus)`、`… (external)`），其余音轨标题本来就是数据（`1. 日语 [jpn] (aac)`），不受影响。见 `README.md` 限制一节。

### info：插件自己生成的纯文本（剪贴板、保存的文件）无法翻译（2026-10-25，info 作者）

- **请求插件 / 代码位置**：`src/plugins/info/about.ts` `aboutText()`（「复制信息」）、`properties.ts` `pageText()`（播放属性的「复制到剪贴板」「保存为…」）。
- **用户操作与预期结果**：中文用户在「关于 Vestra Player」点「复制信息」，或在「播放属性」点「复制到剪贴板」/「保存为…」，得到的文本和窗口里看到的一样是中文（迁移前就是这样）；英文用户得到英文。
- **现有 API 为什么做不到**：这段文本由插件拼好再交出去：`clipboard.writeText(text)` 只收字符串，保存则是插件自己用 Node `fs` 写文件。内容是「标签：值」若干行，标签、单位（`字节`、`核`）、状态词（`运行中`）是固定文字，值是数据。词典只在宿主那边，插件拿不到译文，也不准在 TS 里拼句子。这不属于已知的 r2-api 情形（窗口里的 [string] 列表、嵌套参数、saveFile 的 fileName）：这段文字不经过任何宿主的显示接口，最终要落成一段字符串或一个文件。最小复现：`plugin.clipboard.writeText(\`版本 ${v}\`)`，改成英文原文后，中文用户复制到的就是英文，没有办法把译文拿回来。
- **希望的用法**（两种都行，由维护者选）：
  1. r2-api 的可翻译值也可以交给 `clipboard.writeText`，再加一个只读的格式化：`const text = await plugin.i18n.format(value)`，返回按当前语言翻译、格式化好的字符串，用来写文件。
  2. 只给 `clipboard.writeText(template, args)` 和 `dialogs.saveText({ fileName, text: template, args })` 这类「宿主代写」的接口；行数可变的内容用 r2-api 的列表值表示。
- **状态与资源归谁；失败、取消、能力缺失**：译文和格式化归宿主，与 OSD 模板相同；找不到译文时用英文原文；老播放器（< 0.4.3）没有这个接口时插件照旧写英文。
- **是否破坏现有契约、影响哪些插件**：新增，不破坏。凡是「复制为文本」「导出 .txt/.srt/.csv」并带固定文字的插件都会用到（info 有 3 处；字幕、书签、播放列表的导出可能也有）。
- **最小验收场景**：`startPlugin(activate, { locale: "zh-Hans" })`，在关于窗口触发 `copy-info`，`host.clipboard.text` 以 `Vestra Player\n版本 0.1.0（构建 …）` 开头；保存播放属性得到的文件第一行是 `视频`。
- **附带一点（r2-api 设计时请考虑，不另立请求）**：简要信息（Shift+Tab）每行要按视频区宽度截断（`fit()`，中日韩字符算两列），截断必须在翻译、格式化之后做。r2-api 的 OSD 嵌套参数如果由宿主格式化，插件就量不到最终文字的宽度：需要宿主按列数截断（例如 `OsdPanel.set(value, { maxColumns })`），或者用上面第 1 种的 `format()` 先拿到字符串。

**当前状态**：上面三处文本、播放信息层（Tab / Shift+Tab）、播放属性的各行都暂时是英文，代码里标了 `// i18n: needs r2-api`；窗口自身的文字（标题、页签、按钮、状态、关于窗口的标签、来源和状态词）、菜单、OSD 消息已经可以翻译，中文与迁移前一致。

### marks：新书签的默认标题（2026-10-25，marks 作者）

- **请求插件 / 代码位置**：vestra.marks，`src/plugins/marks/bookmarks.ts` `Bookmarks.add`（默认标题 `Bookmark N`）。
- **用户操作与预期结果**：中文界面按 P 添加书签，书签名应是「书签 1」（0.1.2 及以前如此）；英文界面是「Bookmark 1」。之后用户可以在列表窗口改名。
- **现有 API 为什么做不到**：默认标题不是插件交给播放器显示的模板，而是**存进 bookmarks.json 的数据**：之后作为菜单行（`书签 1    00:10`，与时间拼在一起，按 80 字节截断、去重加 ` (2)`）、OSD 参数、进度条标记标题、列表窗口的可编辑文字出现，并参与搜索。SDK 1.5.9 只有只读的 `plugin.i18n.locale`，没有任何办法得到某条原文在当前语言下的译文字符串，所以 TS 里只能存英文 `Bookmark N`。最小复现：`startPlugin(activate, { locale: "zh-Hans" })` → 按 P → `host.osd.at(-1)` 是「书签：Bookmark 1 已添加（00:10）」，0.1.2 是「书签：书签 1 已添加（00:10）」。
- **希望的用法**（任选其一，由维护者定）：

## 第 2 轮答复（API 维护者，2026-10-25）：文字值

各插件作者的第 2 轮请求写在各自 worktree 的本文件副本里（「第 2 轮请求」各小节）；本节一次答复全部。分支：宿主 `i18n/r2-api`（基于 `origin/i18n/round1`，并入了 D1 `fix/ui-value-limits-main`），SDK `feat/i18n-texts`（基于 SDK 的 `fix/ui-value-limits`，即 1.5.10 D1，版本 **1.5.11**）。

### 分类（§4.2）

全部请求同一根源：用户看得到的文字里固定词与数据混排，或者由翻译过的片段组成，而 TS 不能翻译、不能拼句子（用户裁决）。按 §4.2 第 5 条合并成一个设计议题，不逐条加字段（例如不给 `commands.add` 加只作用于最后一段的 `args`，不给 OSD 单独加 `{text,args}` 参数、给 ComboBox 单独加控件）。属于核心的理由：词典只在宿主，渲染必须在宿主（§4.3 第 1 条），且十几个插件都要用（第 4 条）。

### 设计

一个**文字值**是纯数据，不是译文：

```ts
const { text, list, error, resolve } = plugin.i18n;
text("Track {} · {}", [7, "en"])   // → { $vestraText: "Track {} · {}", args: [7, "en"] }
list(["a.glsl", "b.glsl"])         // → { $vestraList: ["a.glsl", "b.glsl"] }
```

- 参数是数据（字符串、有限数字），或者又是文字值（同样翻译）；嵌套至多 8 层。列表按界面语言连接：`list` `, ` / `、`，`clauses` `, ` / `，`，`semicolons` `; ` / `；`，`sentences` `. ` / `。`，`lines` 换行（日文 `、 、 ； 。`，法文 `;` 前是窄空格；表在宿主 `i18n::text::SEPARATORS` 与 SDK `LIST_SEPARATORS`，host-agreement 检查一致）。
- **宿主渲染**：显示时用该插件的词典查 `source`，再代入渲染过的参数（规则同 `@tr`）；没有译文显示英文。TS 里没有任何翻译调用，`text()` 只是构造数据（`Object.freeze` 的 `{ $vestraText, args }`，构造时检查上限）。
- **一处机制，所有显示面**：命令 `title` / `path` 各段 / `reason`；`osd.show`、`OsdPanel.set` 的文字和参数；确认框各字段；文件对话框 `title`、`saveFile` 的 `fileName`；窗口 / 面板 / 设置页属性里 Slint 类型为 `string` 的任意位置；`TimelineLayer.set` 标题；`subtitles.load` 标题；解析器抛出的 `plugin.i18n.error(…)`。
- **Slint 侧**：Slint 不知道文字值。宿主在 `dispatch` 开头把 `ui.open`、`ui.set`、`ui.mount`、`ui.setMount`、`settings.register`、`settings.set`（以及 `timeline.set`、`subtitles.commit`、`sourceResolvers.respond` 的 `error`）参数里的文字值换成字符串，然后才走原来的路径；`set_property` 收到的只是字符串，`[string]` 的 ComboBox 不用改。`$vestra…` 键不会与真实结构体字段冲突（Slint 标识符不能以 `$` 开头，与 `$vestraImage`、`$vestraMarkdown` 同一约定）。
- **D1 上限**：替换在上限检查之前，所以 `UI_VALUE_LIMITS` 按显示出来的字符串计。文字值自己的上限 `TEXT_LIMITS`：嵌套 8、一个值 1024 个节点、16 个参数、256 项、4096 字节（模板字符串参数从 1024 放宽到 4096 字节）。
- **菜单 key**：Text 段的 key 是它的英文渲染（`Track 2 (opus)`），菜单按 key 合并、绑定表 `key` 给出；显示文字是译文。列表值不能作菜单段。
- **协议**：`vestra/1` 只有新增形状，只在插件用了新 API 时出现；旧插件的字符串与 `args` 语义不变。插件代码运行在播放器自带的 SDK 上，文字值随播放器 0.4.3 出现；用它的插件写 `minPlayerVersion: "0.4.3"`。
- **提取**：`vestra-plugin i18n extract` 收集每个 `plugin.i18n.text(…)` / `error(…)` / `resolve("…")` 的 `source`（字面量、条件两支、`as const` 表；`plugin.i18n.text` 或解构的 `text` 都认，靠类型检查器解析到 `I18n` 接口），以及 `{ $vestraText: "…" }` 字面量；`"{} · {}"` 这类只有占位符和标点的不收录。类型是文字值的字段不再报「不是字面量」。展开进调用选项的字段（`commands.add({ ...extra })`）按类型读取，读不出时报 `… spread into Commands.add is not a literal`。
- **TestHost**：与宿主同样渲染：`FakeCommand.display`（新增不可枚举的 `display.reason`，`deepEqual(display, { title, path })` 的旧测试不变）、`host.osd`、`host.osdPanel`（按 `maxColumns` 截断）、`host.confirmTexts`、新 `host.fileDialogs`、窗口/面板/设置页 `props`（已换成字符串；原样在 `host.sent(…)`）、时间轴与字幕标题、解析器的 `TextError`、`BindingInfo.key`；不合法的文字值同样以 `invalid` 拒绝。
- **`resolve`**（唯一的出口）：同步返回字符串，SDK 在插件进程里读同一份词典（`locales/<lang>.json`，开发时 `.po`）。只用于剪贴板、文件；界面上一律传文字值。
- **截断**：`OsdPanel.set(value, args, { maxColumns })`，宿主在翻译、格式化后按 `unicode-width` 截断每行（宽字符 2 列），末尾 `…`。
