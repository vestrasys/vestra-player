## Open follow-ups

- **Host (API maintainer):** keep a plugin's disabled flag across an update, or `install({ enabled: false })`. Today the host clears it on commit, so a disabled plugin's new version starts briefly before Store 0.2.9 disables it again (VS Code never runs it).
- **Store (plugin author):** store-design §1.3 should say the new version starts briefly and that a cross-source replacement does not keep the disabled state; add a test for reinstalling a disabled plugin from a file or link, and re-read `installedOf` after commit instead of using the pre-dialog state.

- **SDK (API maintainer, docs only):** add the rejection code `previous-crash` to `VideoShaders` and `VideoRender`: the last run ended abnormally with plugin shaders on, so non-empty lists are refused for this start (after a second crash within a day, until the GPU, driver or player changes, or 7 days); clearing still works; do not retry on this code.

- **VestraTube tests (plugin author) or the SDK TestHost (API maintainer):** a flaky Windows CI failure, `ENOTEMPTY` removing the TestHost temp directory at teardown (plugin repo run 41351136515); the rerun passed. Retry the removal (`rm` with `maxRetries`) or find the open handle.

- **Publish gate (accepted residual):** if `video-out-params` still holds the previous file's value at `vf pre`, the new file's first frame through the old chain counts as a new frame; with a different orientation and a stream that stalls right after, a sideways frame can show for about 2 s. Before 0.6.3 this case froze for good.

- **SDK API request (plugin author of shaderupscale → API maintainer):** a plugin cannot tell an orderly stop from a lost host: `runtime.stop` carries no reason and stdin EOF runs the same `stop()`. Request: a reason on `runtime.stop` (`quit` / `disable` / `uninstall` / `reload` / `upgrade` / `idle` / `failed`), `host-lost` when stdin closes without a stop (and for shared-runner members when the runner dies), the reason on `plugin.onDispose(info)`, and TestHost `stop({ reason })` / `disconnect()`; also a `code` argument for TestHost `failVideoShaders` (to simulate `previous-crash`). Until then Shader Upscaling relies on the host's `previous-crash` guard (needs player 0.6.3).
