# Vestra Player 0.6.6 (unsigned test build)

Internal test build, not signed or notarized. Plugins are now looked after by a new plugin supervisor (the design: `doc/architecture/supervisor.md`): a plugin that crashes is handled the same way every time, and quitting no longer waits for plugins one by one.

## Plugins, for everyone

- **Built-in plugins restart by themselves after a crash.** A built-in plugin that stops unexpectedly starts again after 3 seconds, then after 6, 12 … if it keeps crashing; the count starts over once it has run for a minute. If the built-ins that share one process crash together, the first restart is at once, as before, and after three such restarts in a minute each one runs in its own process for the rest of the session, as before.
- **A plugin that crashes over and over is stopped.** After 5 crashes within 10 minutes it stays stopped and Settings ▸ Plugins lists it as failed, saying why; reloading it there starts it again.
- **Failed starts are tried again.** A plugin that cannot be started, or does not get ready in time, is tried up to three more times within about two seconds before it is listed as failed.
- **A notice when a plugin stops.** "*Name* stopped unexpectedly" when a plugin crashes, "*Name* ran out of memory" when it used more than its memory limit, and "*Name* stopped after repeated faults" when it hits the limit above.
- **512 MB of memory per plugin process.** A plugin with its own process may use up to 512 MB of JavaScript memory (the built-ins that share one process keep their 1 GB together). A plugin that needs more stops with "ran out of memory" instead of slowing the whole computer down.
- **Quitting takes at most about a second for plugins.** Every plugin is told to stop at the same time and gets one second in all (before: up to 0.3 s each, one after another; with 40 plugins in our test the player now ends in about 0.1 s after the last frame instead of 0.6 s). After a lost graphics device the restart gives plugins 0.3 s.

## On-demand plugin start (experimental, off by default)

With on-demand start on (`VESTRA_LAZY=1`):

- **Many plugins starting at once no longer freeze the player.** They start a few at a time, clicks first, and their processes are created outside the window's thread: when 200 plugins woke at once in our test, no window update took longer than 7 ms (before: up to 118 ms, and about 30 ms for every plugin started).
- **A crashed plugin keeps its menu entries.** It starts again on its next use after a short pause (1 second, then 2, 4 …). During the pause its menu items are shown disabled with the reason, and a key or click shows "*Name* stopped after a fault; try again in a moment". A plugin that holds something live (a resident plugin) restarts by itself after the same pause.
- **Clear answers instead of silence.** A click a plugin cannot take while it starts shows "*Name* is busy", one waiting for a plugin that is switched off meanwhile "*Name* is disabled", a plugin that fails to start "*Name* could not start" (its menu entries stay, the next click tries again), and a web address whose resolver cannot take it fails at once with that text instead of after 30 seconds.
- **No more 64-plugin ceiling** for plugins starting at the same time.
- A plugin that is still starting holds the clicks sent to it until it is ready, including its first window or panel; reloading a plugin that is still starting keeps the click that started it.

## Installing an unsigned build

- **macOS** 15 or later, Apple silicon: open the DMG and drag Vestra Player into Applications. Gatekeeper blocks the first launch: open System Settings ▸ Privacy & Security and click **Open Anyway**, or run `xattr -dr com.apple.quarantine "/Applications/Vestra Player.app"`. Files downloaded with `gh release download` are not quarantined.
- **Windows** 10/11 x64: run `VestraPlayer-0.6.6-windows-x64-setup.exe`. If SmartScreen warns, choose **More info ▸ Run anyway**. It installs to `%LOCALAPPDATA%\Programs\Vestra Player` without administrator rights. Uninstalling keeps your plugins and settings in `%APPDATA%\Vestra` unless you choose otherwise. Or unzip the portable zip and run `vestra-host.exe` (the portable build adds no Open with entries).

## Known issues

- Check for Updates… reports "no release information was found (HTTP 404)" until a release is published (not a draft) in a public repository; internal test builds cannot find each other.
- Japanese, Korean, German, French and Spanish are machine translations, reviewed once by an AI reviewer; a human review is still to come. The new plugin notices are machine translations not reviewed yet. Corrections are welcome.
- Numbers use "." as the decimal separator in every language (1.5×, 2.0 dB).
- This build is not signed or notarized (see above).
- macOS builds are Apple silicon only. Intel Macs and macOS 14 are not supported yet.
- Picture-in-picture is macOS only. GPU rendering on Windows is experimental and off by default.
