# Vestra Player 0.10.0

This is an internal test build. It is not signed or notarized, and it is for Windows only, like 0.9.0.

0.10.0 ships SDK 1.10.0: events, triggers and the state stream. A plugin can now learn what happens in the player without staying up for it, so fewer plugin processes need to keep running. The player program itself is 0.10.0.

## New

- **Plugins can wait for the player instead of watching it.** A plugin can ask to be told when a video starts to open, is ready, or ends, or hand the player a condition ("playing in fullscreen", "the position is in one of these ranges", "it is 23:00") and be told when it turns true and when it turns false. The player keeps these conditions and checks them itself, also while the plugin is in standby, and starts the plugin only when something happens.
- **The player keeps what a plugin drew or set through standby.** A plugin's marks and ranges on the seek bar and the always-on-top and cursor settings it wrote stay in place while the plugin is stopped, so they no longer keep it running. A new video still clears the seek-bar marks and ranges as before; a crash, disabling, uninstalling, reloading or updating the plugin, and quitting the player remove them.
- **Up to 1000 ranges per plugin on the seek bar** (was 100), as many as marks.
- **The seek bar stays fast with many ranges and marks** (Basic Playback 0.2.20). Ranges and chapter, bookmark and marker ticks are now drawn in small pieces, so their cost grows with their number instead of its square. On a 3840-pixel bar with the default software renderer, 1000 ranges took 40–49 ms a frame and now take about 2.3 ms; a bar with about 3200 ticks took 157 ms a frame and now takes about 10 ms. The bar looks exactly the same.

## Fixes

- **Plugins set aside at start-up each show their own name in the store** (Store 0.2.21). Packages built before 0.9.0, which the player sets aside, all showed the name of the first one; each row now shows its own.
- **Triggers are told about every change, once.** While triggers were built for this release, several cases were fixed before it shipped: a notification that cannot be delivered (the plugin is disabled, failed or too busy) is sent again at the next check instead of the trigger staying quiet; a position report that arrives just behind the player's own does not count as moving back, so there is no spurious leave and enter; replacing a range list while the position stays in the same range does not enter it a second time; a notification on its way cancels a plugin's idle standby instead of stopping the plugin under it.

## Breaking change

- None for users. Plugins built for 0.9.0 keep working unchanged.

## For plugin authors

- **SDK 1.10.0** (see its changelog). Who must change: nobody.
  - **Source events:** `source.opening`, `source.ready` and `source.ended` (with a `reason`: `natural`, `stopped`, `replaced`, `error`, `quit`), through `player.on` without `subscribe()`. They wake a plugin in standby.
  - **Triggers:** `plugin.trigger(name?)` with `.firesOn(condition)`, `.enter(fn)`, `.leave(fn)` and `.off()`, called in the synchronous part of `activate()`. The player keeps and evaluates the condition, also in standby. At most 64 triggers per plugin. A named trigger survives an update of the plugin; an unnamed one is cleared.
  - **The `when` language grows:** `duration`, `volume`, `rate`, `audioTrack(id)`, `subtitleTrack(id)`, `audioDevice(id)`, `muted`, `maximized`, `pip` and `looping`, in triggers and in a command's `enabled` and `checked`; `time({ min?, max? })` and `position.in(ranges, { lead })` (at most 1000 ranges) in triggers only.
  - **`plugin.player.stream(fn)`:** follow every state change while something shows it; the plugin keeps running only while a stream is open.
  - **Timeline layers:** 1000 ranges (was 100), and the layer and the window's on-top and cursor settings are kept by the player through standby.
  - **Two behaviour changes:** an update pass now follows each `plugin.mpv.observe` listener, and a second listener of an observed property gets the current value first.
  - `AudioTrack.streamIndex`; `TestHost` keeps and evaluates triggers and gains a virtual clock (`now`, `advance`), `park()` and `upgrade()`.
  - Set `minPlayerVersion` to `0.10.0` to use the source events, triggers, the kept state or more than 100 ranges: an older player sends no source events, refuses triggers and more than 100 ranges, and everything else works with it.
- The Plugin Workshop is 2.2.44 and vendors SDK 1.10.0.
