# Vestra Player 0.9.0

This is an internal test build. It is not signed or notarized, and it is for Windows only, like 0.8.4.

0.9.0 ships SDK 1.9.0: plugins no longer declare capabilities, panels compile one by one and open faster, and the store and the Plugin Workshop say what a plugin uses from a scan of its code. The player program itself is 0.9.0.

## New

- **No more capability declarations.** A plugin's manifest says only who it is; what the store shows you comes from the scan of its code. The two declarations that changed how a plugin ran are now explicit calls in the plugin's code.
- **Panels compile one by one, when first shown.** Showing or hiding a panel no longer rebuilds the main window, so mounts are faster and the other panels keep their state. A tab in the background compiles when you first open it; the Adjust column compiles its front tabs when it first opens, so switching between them stays instant.
- **The store is open about packages it could not check** (Store 0.2.20). A plugin from a file, a link or another repository now says in its install and update confirmations: "It is not from the official repository, so its permissions were not checked." Another repository's own scan is no longer shown, since it is that repository's claim. Packages from the official repository are listed as in 0.8.4.
- **The Plugin Workshop's install confirmation lists what an AI-generated plugin uses** (Workshop 2.2.43). Before installing it, the Workshop scans the plugin and lists the categories found ("It will be able to: …"), as the store does.

## Fixes

- **Keyboard Shortcuts lists every command after start-up.** A plugin that went idle early in start-up could miss the last changes and show an incomplete list (337 of 372 commands in testing); it is now woken once with what changed.
- **Start-up keeps your remembered sidebar tab.** Until that tab is ready, no other tab is shown, takes the panel keys or starts its plugin.

## Breaking change

- **Third-party plugins built before 0.9.0 are refused.** A package whose manifest still has `capabilities` does not install or start, and the message says what its author must change. There is no compatibility mode. All built-in plugins are already migrated.

## For plugin authors

- **SDK 1.9.0** (see its changelog for the migration):
  - the manifest field `capabilities` is removed and is an error everywhere the SDK reads a manifest;
  - `plugin.player.subscribe()` replaces `events`, and `await plugin.player.read()` replaces `playback.read`, first in `activate()`; nothing else needs a call;
  - set `minPlayerVersion` to `0.9.0`;
  - a panel shown at once still rejects `ready` with `ui-prepare` when it fails to compile; a background tab reports it to `onError` when first shown.
- The Plugin Workshop is 2.2.43 and vendors SDK 1.9.0.

## Known limits

- **Unsigned:** Windows SmartScreen warns on first start.
- **No macOS build in this release.**
