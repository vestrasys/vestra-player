# Vestra Player 0.8.1 (unsigned test build)

This is an internal test build. It is not signed or notarized, and it is for Windows only, like 0.8.0.

0.8.1 does two things:
- It makes Ask Vestra calmer and clearer. You see what it is doing, and it asks once for the whole request.
- It adds the player side of **motion smoothing**, which the new **AMD Motion Smoothing** store plugin turns on.

The player program itself is 0.8.1.

## Ask Vestra

- **A status strip instead of a closed palette.** After you press Enter on Ask Vestra, the palette folds into a thin strip in the same place.
  - While it works, the strip shows what Ask Vestra is doing ("Planning…", then each step), with Stop.
  - When it ends, the strip says what was done or what failed, then fades.
  - You can keep watching the video while it works.
- **One approval for the whole request.** Ask Vestra may plan steps that need your approval, such as a command that deletes or clears something, the player's Close or Quit, a Settings ▸ or Reset ▸ item, or a command of a plugin that is not built in.
  - When it does, the player shows one sheet that lists every step of the plan ("Run these 3 commands?").
  - Enter runs the plan and Esc doesn't. The sheet ignores keys for its first half second, so a key you are still pressing doesn't answer it.
  - It no longer asks once per step.
- **Don't ask again, per plugin.** The approval sheet has a "Don't ask again for <plugin>" checkbox for third-party plugins.
  - It is not offered when the plan contains a step that cannot be undone, or the player's Close or Quit.
  - The choice is forgotten when you uninstall the plugin or install it from another source.
  - Palette command **Command Palette: Ask Again Before Plugin Commands** forgets all of these choices.
- **Confirmations in the player.** Confirmations for the main window (Ask Vestra's first-use consent, the playlist's Remove All, and similar) are drawn inside the player instead of as a separate Windows dialog. Long text scrolls inside the window.
- **Quieter Windows dialogs.** The dialogs that remain, for example in tool windows, no longer beep. Their "don't ask again" boxes are part of the dialog.
- **Fixes:**
  - A plan's later steps no longer fail by running too fast; steps are spaced so they stay within the player's limit.
  - Pressing Enter a second time no longer sends the request again.
  - `host.log` records which command each step ran.

## Motion smoothing (with the AMD Motion Smoothing plugin)

- **What it does.** The new store plugin **AMD Motion Smoothing** (Video ▸ AMD Motion Smoothing…) doubles a video's frame rate with real in-between frames, using the frame-rate converter in AMD's driver (AMF). It needs Windows and an AMD Radeon GPU, and it is off by default.
- **Modes:**
  - **Double Frame Rate**: 24 → 48 fps, 30 → 60 fps.
  - **Match Display**: the doubled frames paced to your display. This mode needs GPU Rendering.
- **Only what can keep up is offered.** A mode is offered only where it was measured to keep the display's rate. For a video it can't do well, the plugin says why instead of stuttering. This includes:
  - videos over 30 fps;
  - 10-bit or HDR video;
  - 4K at 30 fps;
  - 4K with Match Display;
  - 4K with software rendering.
- **Automatic fallback.** If playback still falls behind, the player first switches the converter to a faster search, then turns it off for that video.
- **Exclusions.** Motion smoothing and AI Upscaling don't run together, and neither do motion smoothing and Frame Doubling. Turning one on turns the other off, and the panel says so.
- **Plugin support.** NVIDIA's converter is reserved in the plugin interface and planned as a separate plugin.

## Fixes

- **A crash and freeze on Windows when changing files.** A graphics component could unload the shader compiler, `d3dcompiler_47.dll`, that the player's Direct3D 12 windows still use. The next window update then crashed the player or froze playback. AMD's frame-rate converter did this when it shut down at a file change. The player now keeps that compiler loaded for its whole run, so no component can pull it away.
