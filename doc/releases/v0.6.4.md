# Vestra Player 0.6.4 (unsigned test build)

Internal test build, not signed or notarized. Plugin shaders that take long to compile no longer look like a lost graphics device, a plugin you disabled stays disabled when it is updated, and plugins now learn why they are being stopped.

## Playback and stability (Windows)

- **Heavy plugin shaders no longer restart the player.** The GPU renderer's watchdog took a long first-time shader compile (about 50 seconds for some upscaling networks) for a hang and restarted the player as if the graphics device had been lost; the restart then compiled again. A render call that keeps the CPU busy now counts as progress, for up to 5 minutes.
- **Compiled shaders are cached.** The player keeps compiled shaders in `%LOCALAPPDATA%\Vestra\shader-cache` (`~/Library/Caches/Vestra/shader-cache` on macOS), so a shader set compiles once and later starts show the picture at once. If the folder cannot be used, playback goes on without a cache.
- **Plugin shaders after a GPU failure.** 0.6.3 turned plugin shaders off for the next start only when the player ended while they were drawing. Now a lost graphics device or a stalled renderer also counts when it happens after a plugin changed its shaders and before a frame with them finished on the GPU, while a video is open; changing the source or the window or video size starts that check again. A failure while nothing plays is no longer blamed on plugin shaders.
- **A lost graphics device is quicker to recover from.** The player's windows are hidden as soon as the loss is noticed, and the old process is ended 5 seconds after its windows close (15 seconds at most) instead of waiting for a stuck driver; `restart.log` names the step it was stuck in.
- **Full screen with a monitor next to it** (Windows): the extra row of pixels that keeps the window out of exclusive full screen now goes to an edge with no other monitor behind it.
- **Less memory while nothing is open**: the software renderer's frame buffers are released when you close the file.

## Plugin Store

- **A plugin you disabled stays disabled when it is updated or reinstalled**, from any source; the new version is installed but not started. A first install still enables it.
- **A version the store disabled because its repository revoked it is enabled again by updating to the fixed version** (Store 0.2.10), and the store reports it if the fixed version then fails to start.

## Vestra Player AI

- After installing a plugin it made, the AI is told whether the plugin is running, kept disabled by you (it asks you to enable it in the Plugin Store and never enables it itself) or failed (Workshop 2.2.26).
- It knows the SDK 1.5.54 and 1.5.55 additions (Workshop 2.2.27).

## For plugin authors

SDK 1.5.54–1.5.55 (`@vestra-player/sdk`); `apiVersion` stays `vestra/1`. Documentation: [vestrasys.github.io/vestra-player-sdk](https://vestrasys.github.io/vestra-player-sdk/).

- **Stop reasons.** The player tells a plugin why it stops: `quit`, `disable`, `uninstall`, `reload`, `upgrade`, `idle` or `failed`, and the plugin reads `host-lost` when the player went away without a stop. Read `plugin.stopReason` or the `info` argument of `onDispose`. Some stops still arrive without any message (a shared plugin process restarting, a plugin that failed to activate, a process that already exited); keep state you need in storage as you go.
- **`install({ enabled })`**: `true` enables and starts the plugin, `false` installs it disabled; without it an update keeps the installed plugin's state.
- **`previous-crash`**: the rejection code for plugin shaders turned off after a crash is now documented.
- **TestHost**: an update of a disabled plugin stays disabled, as in this player; set `host.installKeepsDisabled = false` to test against older players.

## Installing an unsigned build

- **macOS** 15 or later, Apple silicon: open the DMG and drag Vestra Player into Applications. Gatekeeper blocks the first launch: open System Settings ▸ Privacy & Security and click **Open Anyway**, or run `xattr -dr com.apple.quarantine "/Applications/Vestra Player.app"`. Files downloaded with `gh release download` are not quarantined.
- **Windows** 10/11 x64: run `VestraPlayer-0.6.4-windows-x64-setup.exe`. If SmartScreen warns, choose **More info ▸ Run anyway**. It installs to `%LOCALAPPDATA%\Programs\Vestra Player` without administrator rights. Uninstalling keeps your plugins and settings in `%APPDATA%\Vestra` unless you choose otherwise. Or unzip the portable zip and run `vestra-host.exe` (the portable build adds no Open with entries).

## Known issues

- Check for Updates… reports "no release information was found (HTTP 404)" until a release is published (not a draft) in a public repository; internal test builds cannot find each other.
- Japanese, Korean, German, French and Spanish are machine translations, reviewed once by an AI reviewer; a human review is still to come. Corrections are welcome.
- Numbers use "." as the decimal separator in every language (1.5×, 2.0 dB).
- This build is not signed or notarized (see above).
- macOS builds are Apple silicon only. Intel Macs and macOS 14 are not supported yet.
- Picture-in-picture is macOS only. GPU rendering on Windows is experimental and off by default.
