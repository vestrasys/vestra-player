# Vestra Player 0.6.4 (unsigned test build)

Internal test build, not signed or notarized. Plugin shaders that take long to compile no longer look like a lost graphics device, a plugin you disabled is no longer started when it is updated, and plugins now learn why they are being stopped.

## Playback and stability

- **Heavy plugin shaders no longer restart the player** (Windows, GPU rendering). The GPU renderer's watchdog took a long first-time shader compile (about 50 seconds to several minutes for some upscaling networks) for a hang and restarted the player as if the graphics device had been lost; the restart then compiled again. While a render call keeps the CPU busy, its 30-second limit now pauses instead of running out; a single call may take up to 5 minutes.
- **Compiled shaders are cached** (GPU rendering). The player keeps compiled shaders in `%LOCALAPPDATA%\Vestra\shader-cache` (`~/Library/Caches/Vestra/shader-cache` on macOS), so a shader set compiles once and later starts draw their first frame at once. If the folder cannot be created or used, playback goes on without a cache. Uninstalling does not remove this folder.
- **Plugin shaders after a GPU failure** (Windows, GPU rendering). 0.6.3 counted a failure against plugin shaders only when the player ended while they were drawing. Now a lost graphics device or a stalled renderer also counts when it happens after a plugin changed its shaders and before a frame with them finished on the GPU, while a video is open; changing the source, the window size or the video size starts that check again. A failure while no video is open, or with audio only, is not blamed on them.
- **A lost graphics device is quicker to recover from** (Windows). The player's windows are hidden as soon as the loss is noticed, and the new player starts at once. If the old process has not ended 5 seconds after its event loop ends, or 15 seconds after the restart at most, it is ended without waiting for the driver (0.6.3 waited 15 seconds in every case); `restart.log` names the step it was stuck in.
- **Full screen with a monitor below it** (Windows): the extra row of pixels that keeps the display from blanking when the window covers it exactly no longer shows on the monitor below; it goes past an edge with no monitor beyond it (top, right or left), and with monitors on every side the window is one pixel short instead.
- **Less memory while nothing is open** (software rendering, the Windows default): when you close the file the player frees the frame buffers it draws video into (up to about 75 MB at 4K), and it draws nothing until a file is open.

## Plugin Store

- **A plugin you disabled is no longer started when it is updated or reinstalled**, from any source: the player installs the new version and keeps it disabled (0.6.3 started it and the store turned it off again). A first install still enables it. Such an update is not test-started, so a broken version shows as failed only once you enable it.
- **Updating a revoked version the store disabled to the fixed version still enables the fix** (Store 0.2.10): the store now enables it after the install, waits for it to start, and says so if it could not be enabled or failed to start.

## Vestra Player AI

- After installing a plugin it made, the AI is told whether the plugin is running, kept disabled by you or failed; for a disabled plugin the result card points you to the Plugin Store, and the AI never enables it itself (Workshop 2.2.26).
- It knows the SDK 1.5.54 and 1.5.55 additions (Workshop 2.2.27).

## For plugin authors

SDK 1.5.54–1.5.55 (`@vestra-player/sdk`); `apiVersion` stays `vestra/1`. Documentation: [vestrasys.github.io/vestra-player-sdk](https://vestrasys.github.io/vestra-player-sdk/).

- **Stop reasons.** The player tells a plugin why it stops: `quit`, `disable`, `uninstall`, `reload`, `upgrade`, `idle` or `failed`, and the plugin reads `host-lost` when the player went away without a stop. Read `plugin.stopReason` or the `info` argument of `onDispose`. `idle` comes only with lazy activation, which is off by default. In some cases the plugin is ended without a stop and its `onDispose` cleanups do not run: when a shared plugin process restarts, when a plugin in its own process fails to activate or its input backs up, and when the process has already exited; keep state you need in storage as you go.
- **`onDispose` cleanups get one argument.** With this player every cleanup receives `DisposeInfo`, whatever SDK the plugin was built with: wrap a function that takes optional parameters of its own (`() => controller.abort()`, not `controller.abort.bind(controller)`).
- **`install({ enabled })`**: `true` enables and starts the plugin, `false` installs it disabled and also stops a running version; without it an update keeps the installed plugin's state. Players up to 0.6.3 ignore the option and every install runs.
- **`previous-crash`**: the rejection code for plugin shaders turned off after a crash is now documented.
- **TestHost**: an update of a disabled plugin stays disabled, as in this player; set `host.installKeepsDisabled = false` to test against older players.

## Installing an unsigned build

- **macOS** 15 or later, Apple silicon: open the DMG and drag Vestra Player into Applications. Gatekeeper blocks the first launch: open System Settings ▸ Privacy & Security and click **Open Anyway**, or run `xattr -dr com.apple.quarantine "/Applications/Vestra Player.app"`. Files downloaded with `gh release download` are not quarantined.
- **Windows** 10/11 x64: run `VestraPlayer-0.6.4-windows-x64-setup.exe`. If SmartScreen warns, choose **More info ▸ Run anyway**. It installs to `%LOCALAPPDATA%\Programs\Vestra Player` without administrator rights. Uninstalling keeps your plugins and settings in `%APPDATA%\Vestra` unless you choose otherwise. Or unzip the portable zip and run `vestra-host.exe` (the portable build adds no Open with entries).

## Known issues

- Check for Updates… reports "no release information was found (HTTP 404)" until a release is published (not a draft) in a public repository; internal test builds cannot find each other.
- The new texts of 0.6.4 (Plugin Store and AI install messages) are machine translations not yet reviewed.
- Japanese, Korean, German, French and Spanish are machine translations, reviewed once by an AI reviewer; a human review is still to come. Corrections are welcome.
- Numbers use "." as the decimal separator in every language (1.5×, 2.0 dB).
- This build is not signed or notarized (see above).
- macOS builds are Apple silicon only. Intel Macs and macOS 14 are not supported yet.
- Picture-in-picture is macOS only. GPU rendering on Windows is experimental and off by default.
