# Vestra Player 0.11.0

This is an internal test build. It is not signed or notarized, and it is for Windows only, like 0.10.3.

0.11.0 lets plugins rest while nothing uses them: most built-in plugins now stop when idle and start again when you use them or when something they follow happens. The player program is 0.11.0; the SDK goes to 1.11.0.

## Breaking change

- **Some store plugins must be updated.** Store plugins installed before 0.11 that follow the player's state the old way fail when they start until you update them: Auto Frame, Clip Export, Loudness, Shader Upscale and VestraTube. The Plugin Store offers the updates: open it, go to Updates and click Update on each card (Auto Frame 0.1.3, Clip Export 0.8.3, Loudness 0.1.2, Shader Upscale 0.3.3, VestraTube 0.5.6). The other store plugins keep working unchanged.

## Improvements

- **More built-in plugins rest while idle.** History, Online Subtitles, Window, Info and Marks now stop while nothing uses them, as Preferences, the store, Capture, Hotkeys and the Workshop already did, and start again on their next use: opening a file, a menu item or key, their tab or window, or a change they follow (a new file, a device plugged in, the window going fullscreen). Playback, the playlist, Audio, Video, the visualizer and Subtitles keep running, as they show or apply something all the time. Nothing changes in what you see (Audio 1.5.14, History 0.1.11, Info 0.1.18, Marks 0.1.12, Playback 0.2.21, Playlist 0.2.12, Preferences 0.3.7, Store 0.3.4, Online Subtitles 0.1.9, Subtitles 0.4.15, Video 1.1.16, Visualizer 0.1.12, Window 0.1.10).
- **Less memory on Windows.** The player now uses Windows' newer segment heap, which returns freed memory to the system sooner: about 20–45 MB less private memory with CPU rendering (idle 188 → 161 MB, 1080p 263 → 238 MB, 4K 406 → 387 MB, with the adjust panels 464 → 429 MB), about the same with GPU rendering. Frame rate, start-up time and CPU use are unchanged. Windows 10 before version 2004 ignores the setting.
- **The command palette's button shows a magnifier** with the AI sparkle while a plugin offers its first row.
- **Vestra Player AI writes plugins that rest while idle**, sets their minimum player version to the player you use (at least 0.11.0), and checks in their tests that nothing keeps them running while idle (Workshop 2.2.47).

## Fixed

- **The Plugin Store and Vestra Player AI windows resize properly again.** The Plugin Store can be made as tall as the screen, can no longer be squeezed below 480 pixels, opens 640 high again, and its cards no longer jump while the window is resized: the card at the top left stays in the top row when the number of columns changes. The Vestra Player AI window can be made wider than 720 pixels again, no longer gets narrower than that, and opens 900 wide (Store 0.3.3, Workshop 2.2.47). The same hidden-element pattern was made safe in the About, Properties, Marks and Add Links windows, which were not affected (Info 0.1.17, Marks 0.1.11, Playlist 0.2.11).
- **Online Subtitles keeps its search results** when the same file plays again after its end; only another file clears them.
- **The Chapter and Bookmark List empties when the file is closed**, also after the file played to its end.

## For plugin authors

- **SDK 1.11.0** (see its changelog). Who must change: a plugin that calls `player.subscribe()` or `player.onChange()` (both removed), a tool that runs `vestra-plugin scan`, and a plugin that compares `error.code` for a built-in-only call (now `builtin-only`).
  - An event reaches a plugin from its first listener; `subscribe()` is no longer needed.
  - New events that wake a resting plugin: `video.reconfigured`, `audio.reconfigured`, `audio.tracks.changed`, `subtitles.changed`, `window.changed`, `layout.changed`, `audio.devices.changed` and `app.started`.
  - Learn the player's state in one of four ways: read it once (`await plugin.player.read()`), listen to events, set triggers on `plugin.when` conditions, or open a stream (`plugin.player.stream`) while something on screen shows the state. Only the stream keeps the plugin running. A command's enabled or checked state is a `plugin.when` condition, which the player keeps while the plugin rests.
  - The display layer, a shader channel and a filter keep a plugin running through what they hold, not as a listener of the player's state.
  - Plugins have no capability list any more: the store no longer shows what a plugin's code uses, and the SDK's capability scan is gone.
  - Once the player has sent `runtime.stop`, a plugin's further requests are refused and not sent.
- The new SDK guide *Learn what happens in the player without staying up* shows the patterns.
- The Plugin Workshop is 2.2.47 and vendors SDK 1.11.0.

## Known limits

- **Unsigned:** Windows SmartScreen warns on first start: click "More info", then "Run anyway". The installer needs no administrator rights; you can also unzip the portable zip and run `vestra-host.exe`.
- **No macOS build in this release.**
