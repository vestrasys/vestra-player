# Vestra Player 0.10.2

This is an internal test build. It is not signed or notarized, and it is for Windows only, like 0.10.1.

0.10.2 makes the player more responsive: its core now runs on its own thread, so a busy window no longer holds up plugins or playback control. The player program itself is 0.10.2; the SDK stays 1.10.0.

## Improvements

- **A busy window no longer holds up plugins and playback control.** The player's core (plugin requests, triggers, plugin start and stop, playback control) now runs on its own thread instead of inside the window's event loop. While a window is being built, dragged or resized, or waits for the graphics card, plugins keep getting answers, timed triggers fire on time, idle plugins are put to standby on time, and Play/Pause still reaches playback. Measured with the window held for 4 s: 99% of plugin requests were answered within 35 ms (before: over 4 s).
- **Faster answers to plugins.** The core now handles each request when it arrives instead of on a 16 ms tick: most requests that change the interface are answered within about a millisecond (a panel property change: 0–1 ms, before 30 ms; a settings write: 2–3 ms, before about 31 ms). The window's own frame rate is unchanged.
- **The window keeps drawing while it is moved or resized** (the player's tick keeps running inside the system's move/size loop).
- **File dialogs no longer hide behind a fullscreen player.** With the player fullscreen and always on top, file dialogs (open, save, folder, locate) stayed behind it and every shortcut seemed dead. They now belong to the window that asked, a key or click that the open dialog blocks brings the dialog forward, and the player is not on top while a dialog is open.
- **"Always on top" now defaults to Never** (Window 0.1.9), as in mpv and VLC. If you never chose a mode, the player no longer stays on top in fullscreen; a mode you chose is kept. To get the old behaviour back, pick "While Playing in Fullscreen" once.
- **A new plugin store** (Store 0.3.1): plugins are shown as a card grid, with a Not installed tab, a filter for built-in plugins, and the actions on each card. Each card says where to open the plugin in the player, also before you install it.

## Breaking change

- None. Plugins built for 0.10.0 keep working unchanged.

## For plugin authors

- No SDK or wire change: SDK 1.10.0 as in 0.10.0. Who must change: nobody.
- Replies to requests a plugin sends at the same time (without waiting between them) were never promised in any order, and now arrive in whatever order they are ready: a reply that waits for the playback worker (`source.state`, for example) may come before or after the reply to another request sent with it. Each reply is matched to its request by id, as always.
- The built-in plugins' descriptions end with a line starting with `→ ` that says where to open the plugin; the store shows it on the plugin's card. A store plugin can do the same, with at most 48 characters after the arrow.

## Known limits

- **Unsigned:** Windows SmartScreen warns on first start: click "More info", then "Run anyway". The installer needs no administrator rights; you can also unzip the portable zip and run `vestra-host.exe`.
- **No macOS build in this release.**
