# Vestra Player 0.7.0 (unsigned test build)

Internal test build, not signed or notarized. Plugins now start when they are needed and rest when they are not, so many installed plugins cost little memory; a plugin that crashes is handled the same way every time; and the AI chat's answers can be selected and copied. (0.6.6, 0.6.7 and 0.6.8 were internal builds only; their changes are all here.)

## Plugins start when they are needed

- **Plugins rest when idle.** The first time the player runs a plugin it learns its menu items, keys, settings pages and the files and addresses it opens. After that, a plugin that holds nothing live (no playback listener, no open window or panel) is put in standby: no process runs, but everything it added stays in the menus and works. The first use starts it again, and 30 seconds without use puts it back. With 50 plugins installed, our test machine used about 3.6 GB less memory while they were idle.
- **A click on a resting plugin takes a moment.** In our tests a command of a plugin in standby ran about 0.2 s after the click (0.3 s for a large plugin); a built-in plugin was ready within 0.1 s. A plugin that needs longer shows "Starting *name*…".
- **Plugins that hold something live keep running.** A plugin that listens to playback, or keeps a window or panel open, when it starts is never put in standby.
- **Many plugins starting at once no longer freeze the player.** They start a few at a time, clicks first, and their processes are created outside the window's thread. When 200 plugins woke at once in our test, the player kept drawing smoothly.
- **Clear answers instead of silence.** A click a starting plugin cannot take shows "*Name* is busy"; one waiting for a plugin that is switched off meanwhile, "*Name* is disabled"; a plugin that fails to start, "*Name* could not start" (its menu entries stay, the next click tries again). A web address whose resolver cannot take it fails at once with that text instead of after 30 seconds.
- **Reloading a plugin that is still starting keeps the click that started it**: the click is delivered once the reloaded plugin is ready.
- **No more 64-plugin ceiling** for plugins starting at the same time.
- Settings ▸ Plugins shows a plugin in standby as running and `idle`.

## Crashes and stuck plugins

- **Built-in plugins restart by themselves after a crash**, after 3 seconds, then 6, 12 … if they keep crashing; the count starts over once a plugin has run for a minute. If the built-ins that share one process crash together, the first restart is at once, and after three such restarts in a minute each built-in runs in its own process for the rest of the session.
- **Other plugins keep their menu entries after a crash.** They start again on their next use after a short pause (1 second, then 2, 4 …, at most a minute). During the pause their menu items show disabled with the reason, and a click shows "*Name* stopped after a fault; try again in a moment". A plugin that holds something live restarts by itself after the same pause.
- **A plugin that crashes over and over is stopped.** After 5 crashes within 10 minutes it stays stopped and Settings ▸ Plugins lists it as failed, saying why; reloading it there starts it again.
- **A notice when a plugin stops**: "*Name* stopped unexpectedly", "*Name* ran out of memory", or "*Name* stopped after repeated faults".
- **A plugin stuck starting is reported after 60 seconds**, once: a click waiting for it is answered "*Name* could not start", and the plugin then follows the rules above. A plugin whose process could not be created at all is tried again three times within about two seconds.
- **A plugin that leaves a web address it was asked to resolve unanswered for 5 minutes is stopped** and treated like a crash. Work a plugin declares as busy (a long command, an open settings page) has no limit.

## Memory

- **512 MB of memory per plugin process.** A plugin with its own process may use up to 512 MB of JavaScript memory (the built-ins that share one process keep their 1 GB together). A plugin that needs more stops with "ran out of memory" instead of slowing the whole computer down.
- **A cap on how many third-party plugins run at once**: 3 to 16 processes, depending on the computer's memory (14 with 8 GB, 16 from about 9 GB). Starting one past the cap puts the least recently used idle plugin in standby. A busy plugin is never put in standby for this, and built-in plugins are not counted.
- **When the computer runs low on memory**, idle third-party plugins go to standby at once (Windows: when less than about 1 GB of memory is available; Linux: from the kernel's memory pressure reading). Under critical pressure a click waits for a free place instead of starting one more plugin.
- **Built-in plugins no longer count toward the limit of installed plugins.** Past the limit, the newest third-party installs are set aside (not those first by name), and their data stays reachable.

## Stopping and quitting

- **More time to clean up.** Switching a plugin off, reloading, uninstalling or updating it, or putting it in standby gives it up to 5 seconds to finish its cleanup (before: 0.3 s, and 2 s for standby).
- **Quitting takes at most about a second for plugins.** Every plugin is told to stop at the same time and gets one second in all (before: up to 0.3 s each, one after another). After a lost graphics device the restart gives plugins 0.3 s.

## AI chat

- **One activity row per turn.** While the AI works the row reads "Working…" and the latest step; when the turn is over it reads "Worked for 12 seconds · 3 steps", and a click lists the steps. The model's thinking is no longer shown.
- **Answers can be selected and copied.** Drag over a paragraph, heading, list item or quote of an answer to select it; Ctrl+C (⌘C on macOS) copies it, and a right click offers Copy and Select All. Code blocks can be selected the same way everywhere Markdown is shown. A paragraph with links keeps its clickable links: a right click copies it as text with each address after its link, `text (https://…)`, and offers Copy Link when it has one link. A selection stays inside one paragraph or block.

## Smoother with many plugins

- With a hundred or more plugins installed, the player no longer rebuilds the plugin list and the key list several times a second to look for changes; it does so only when something changed. On 120 and 144 Hz displays this removes the occasional dropped frame it caused, also while many plugins start at once.

## For plugin authors

- **SDK 1.6.0: selectable Markdown in plugin UIs.** `MarkdownBlocks` and `MarkdownView` have `selectable` (off by default; nothing changes for views that do not set it, except code blocks, which are now always selectable), and `MarkdownBlock` has `plain` and `links`.
- Plugins need no changes for on-demand start. The SDK documentation describes the timings and what keeps a plugin running.

## Installing an unsigned build

- **macOS** 15 or later, Apple silicon: open the DMG and drag Vestra Player into Applications. Gatekeeper blocks the first launch: open System Settings ▸ Privacy & Security and click **Open Anyway**, or run `xattr -dr com.apple.quarantine "/Applications/Vestra Player.app"`. Files downloaded with `gh release download` are not quarantined.
- **Windows** 10/11 x64: run `VestraPlayer-0.7.0-windows-x64-setup.exe`. If SmartScreen warns, choose **More info ▸ Run anyway**. It installs to `%LOCALAPPDATA%\Programs\Vestra Player` without administrator rights. Uninstalling keeps your plugins and settings in `%APPDATA%\Vestra` unless you choose otherwise. Or unzip the portable zip and run `vestra-host.exe` (the portable build adds no Open with entries).

## Known issues

- The first start after updating starts every plugin once (each plugin's first run, to learn what it adds); later starts are lighter.
- Check for Updates… reports "no release information was found (HTTP 404)" until a release is published (not a draft) in a public repository; internal test builds cannot find each other.
- Japanese, Korean, German, French and Spanish are machine translations, reviewed once by an AI reviewer; a human review is still to come. The new plugin notices are not reviewed yet. Corrections are welcome.
- Numbers use "." as the decimal separator in every language (1.5×, 2.0 dB).
- This build is not signed or notarized (see above).
- macOS builds are Apple silicon only. Intel Macs and macOS 14 are not supported yet.
- Picture-in-picture is macOS only. GPU rendering on Windows is experimental and off by default.
