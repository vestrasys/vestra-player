# 实验 1 的实现与验证记录

> 实验版本；接口可能与最终成品 API 相差很大。更新日期：2026-10-04。

Rust Slint 宿主、Node TypeScript 运行时、文件播放、高斯模糊及播放列表插件现已完成编译，并运行了真实桌面窗口的自动实验。这里验证的是现有的“重建窗口”路线，没有使用 Slint 内部动态嵌入接口，也没有实现完整插件安装管理器。

## 播放列表侧栏的结论

**首次加载未知侧栏仍需组合、编译界面并替换窗口；之后隐藏和重显侧栏不需要重新编译，也不需要替换窗口。**

侧栏采用原生 Slint 条件组件。隐藏后视频区获得释放的空间；重显时侧栏组件重新实例化，但播放器窗口不重建。条目、当前页和可见状态由 TS 插件持有，通过已有属性桥更新，不增加按钮注册 API。

实际窗口实验通过：初始窗口加文件插件后计数为 2；加入播放列表后编译次数和窗口代数变为 3；隐藏和展开均保持 3；再加入滤镜后变为 4，列表条目和展开状态保留。播放后端保持同一个实例，当前位置继续推进，没有重新从头播放。逐阶段数据见 [原始报告](evidence/playlist-window-report.json)。

截图：[侧栏展开](evidence/playlist-shown.png)、[侧栏隐藏](evidence/playlist-hidden.png)。截图来自 Slint 的公开窗口快照接口。首次加载仍有编译停顿和窗口替换；本次未量化肉眼闪动或保证焦点、全屏状态完整保留。

实际编译修复了旧实验中 Window 同时设置固定尺寸与最小尺寸的错误，以及在宿主引用 re-export global 时缺少 import 的错误。截图检查也修正了视频 Image 的尺寸约束和操作栏进度条的最小宽度。

## 复现

需要 Rust 1.92+、Node 22.18+、FFmpeg 工具和依赖下载网络；窗口实验另需桌面图形环境。

```sh
./scripts/check.sh --gui
./scripts/playlist-experiment.sh
./scripts/run.sh
```

窗口实验成功后自动退出，将 JSON 和两张截图写入 evidence/。默认交互启动通过右键添加各插件 manifest。

## 边界与取舍

- 插件作者写原生 .slint 布局与 TS 行为；当前属性桥只支持 string、number、boolean，不是 Slint 全功能绑定。
- sidebar 是此次实验专用挂载点，只接受一个侧栏；不是已经确定的 placement 或 docking 协议。现有文件和滤镜面板仍沿用最初实验的下方布局，不代表最终产品允许插件任意堆叠面板。
- 隐藏侧栏会销毁其条件组件，重显重新创建。TS 持有的列表可恢复，但焦点、滚动位置等仅存在于组件里的局部状态需要另外保存。
- Rust 保留播放会话、时钟和视频帧；TS 不收发逐帧像素。退出整个应用后的持久化续播没有实现。
- 后端仍是 FFmpeg CPU gblur、640×360、30 FPS 预览，不是 mpv 或 GPU 性能实验。改变滤镜、跳转会重建处理管线。
- 独立 ffplay 音频仅粗同步；编译界面、探测文件及部分进程启停仍在 GUI 线程，可能短暂停顿。
- 本地可信插件拥有 Node 运行时权限，独立进程不是沙箱。宿主退出直接回收子进程，不保证异步清理函数完成。

此次验证表明：播放列表的日常显示/隐藏可以用稳定 Slint API 完成；“首次加载未知界面而不重建窗口”仍是另一个问题，本实验没有解决它。
