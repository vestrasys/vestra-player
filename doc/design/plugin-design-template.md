# 插件方案模板

这是设计阶段交付模板，不是实现任务，也不表示 API 已批准。作者只能读取本轮新实现和已获授权的需求文档，不读取旧实现。统一规范以 product-interaction.md 和 menu-map.md 的最新审查版本为准；若二者尚未就绪，先等待，不自行决定全局菜单。

## 1. 职责与使用场景

说明用户要完成什么、插件负责什么、哪些能力由公共宿主提供。列有限功能范围、非目标和没有其他功能插件时的使用前提。不得隐藏依赖其他插件。

## 2. 入口与命令表

| 功能 | 唯一主菜单路径 | 按钮/快捷键等其他必要入口 | 直接执行或打开界面 | 启用条件 | 权威状态来源 |
| --- | --- | --- | --- | --- | --- |

使用统一规范预留的路径，逐条给出命令名称。复位、预设和子功能留在所属领域，不再散放通用工具菜单。若必须更改全局路径，提交建议及理由，不自行批准。

## 3. 界面与生命周期

提供简单草图及控件顺序，说明界面形式、默认显示状态、尺寸/滚动、打开/关闭/再次打开、焦点与键盘输入、与主画面和常驻播放栏的关系。界面关闭、功能撤销与插件停用分别定义；不让隐藏界面决定处理资源是否存活。

## 4. 状态、连续交互与失败

覆盖无媒体、加载中、播放中、暂停中、来源切换、连续拖动、重复点击及异步任务。明确何时参数已提交、何时实际生效，旧结果如何隔离，取消如何反馈、失败如何恢复。对文件操作说明系统对话框确认/取消、无效文件及已有输出的行为。

## 5. 公共 API usage 与缺口

用最少的 TS/Slint 例子说明作者希望如何调用。逐项标记“初版已有”“请求扩展”“仍待设计”，不将伪代码描述为可运行 SDK。每个能力请求包含所有者、资源/会话、输入输出、错误/取消、清理及最小观察场景；发送给 API maintainer 评估。不能通过读写兄弟插件或宿主私有对象绕过。

## 6. 验收场景

| 场景 | 用户实际操作 | 可以观察的结果 | 需要的证据 | 独立/组合条件 |
| --- | --- | --- | --- | --- |

按钮与菜单入口分别盘点；实际鼠标/键盘、系统面板、后端产物与回调测试分别注明。需要媒体/ROM的样本由本轮新建或合法来源提供，不能读取旧测试副本。连续调参必须观察播放是否中断，不能只判断参数请求返回成功。

## 7. 审查与版本

记录方案版本、关联全局规范版本、API 请求、交互负责人意见、maintainer 意见、必要修改与结论。只有集中审查通过并收到共同开发基线及实现任务后才开始产品代码。
