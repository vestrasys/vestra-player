## 1. 职责与使用场景

本插件持有本次运行内的本地媒体队列、选择、排列、错误和自动推进策略，提供多文件添加、显式播放、上一/下一、移除、移动、清空与侧栏显隐。公共宿主持有主画布、普通媒体播放设施、来源会话身份、原生组件挂载、命令路由和文件选择器。基础播放插件既不是依赖，也不是本插件可读取或调用的对象。

有限范围为顺序队列，末项自然结束后停止。没有持久化、随机、循环、网络列表、目录递归、拖放导入、播放历史或文件管理器承诺。侧栏关闭后队列仍工作；停用插件后队列策略停止，当前媒体由公共宿主持有并继续。重新启用为新的空队列，不暗中接管仍在播放的来源。

独立运行只需要支持本方案必要公开能力的统一宿主，不安装基础播放和其余六插件也应能添加、选播、按序推进及停用。缺基础播放栏时主画布仍由宿主呈现；本插件不补造另一套底栏。

## 2. 入口与命令表

以下是插件内部命令名提议，不代表已批准 SDK 注册签名。所有副入口进入同一 action，菜单与按钮共享 enabled、checked、忙碌状态。右键投影全局菜单树，不另注册菜单逻辑；本方案不增加全局快捷键。

| 功能 / 命令 | 唯一主菜单路径 | 其他入口 | 执行方式 | 启用条件 | 权威状态来源 |
| --- | --- | --- | --- | --- | --- |
| 添加 / `playlist.add` | 文件→播放列表→添加文件… | 侧栏“添加…” | 非阻塞系统多选文件面板 | 无进行中的本插件选择请求，文件选择能力可用 | 公共选择结果；插件队列 |
| 播放 / `playlist.play` | 文件→播放列表→播放选中项 | 侧栏“播放”；行双击；列表焦点下 Enter | 显式打开所选文件 | 有选中行，非打开结果未知；本插件打开请求未结算时禁重复 | 选中 row ID；公开会话加载结果 |
| 上一 / `playlist.previous` | 文件→播放列表→上一项 | “上一项”按钮 | 显式打开相邻项 | 有锚点且存在前一项，打开动作可用 | 插件当前受控/失败目标行，否则选中行 |
| 下一 / `playlist.next` | 文件→播放列表→下一项 | “下一项”按钮 | 显式打开相邻项 | 有锚点且存在后一项，打开动作可用 | 同上 |
| 移除 / `playlist.remove` | 文件→播放列表→移除选中项 | “移除”；列表焦点下 Delete | 立即编辑队列 | 有选中行 | 插件队列/选择 |
| 上移 / `playlist.move-up` | 文件→播放列表→上移 | “上移” | 交换相邻行 | 选中行不是首行 | 插件队列顺序 |
| 下移 / `playlist.move-down` | 文件→播放列表→下移 | “下移” | 交换相邻行 | 选中行不是末行 | 插件队列顺序 |
| 清空 / `playlist.clear` | 文件→播放列表→清空列表 | “清空” | 清空本次运行队列，无文件删除 | 队列非空 | 插件队列 |

菜单隐藏侧栏时仍可添加和选播已有选择，不强制弹出侧栏或抢焦点。没有选择时不以首项代替选中项，播放菜单禁用；首次添加到空队列后选中首个新增行，但不播放。

## 3. 界面与生命周期

```text
┌ 文件 播放 视频 音频 字幕 视图 模拟器 插件 ┐
│ 主画布：contain，至少640×360 │播放列表  × │
│                              │添加… 播放 │
│                              │↑上一 ↓下一│
│                              │▶ 1 文件A  │
│                              │  2 文件B !│
│                              │列表可滚动 │
│                              │移除 上移  │
│                              │下移 清空  │
│                              │状态/原因  │
├───────────────────────────────────────────┤
│ 独立公共底部挂载：基础播放插件常驻操作栏   │
└───────────────────────────────────────────┘
```

右侧栏默认显示，目标宽280、最小240逻辑像素。视图勾选 `checked` 表示宿主确认的用户显隐偏好 `preferred`，实际呈现 `effective` 及 space/fullscreen 暂隐原因另列；空间不足自动收起和全屏暂隐均不改变偏好。标题关闭按钮或用户主动取消菜单勾选明确将偏好设为 false，不能只请求一次临时隐藏。宿主负责主窗尺寸和空间判断；底栏横跨整个主窗，侧栏只占上方画布横向空间，无权占用/替换底栏挂载。可见侧栏须保留画布640×360，空间不足收起并显示“空间不足，放大窗口后可显示”。保留队列、选择和用户偏好，放大后不抢焦点。空间不足时显示命令先请求把普通窗口放大，屏幕仍不足则保持收起并解释。全屏按 B1 先隐藏，普通窗口偏好不变；全屏手动显示仍受画布最小面积约束。不提供独立窗口替代形态。

标题、按钮区、底部状态区保持可达，队列区域滚动。每行显示序号、文件名、加载/播放/暂停/结束/失败标记；长名省略，完整本地路径和错误用可访问说明或行详情显示。选择高亮与“当前播放”图标分开：单击/方向键只选择，Enter/双击才播放。只承诺单选列表，文件面板支持多选。

选择时只滚动到所选行；后台加载结果不移动选择、滚动或焦点。通过菜单显示时焦点进入列表（空列表为添加按钮）；用户关闭时恢复仍存在的主窗焦点。列表方向键用于选择，Delete移除，Enter选播；编辑器/系统文件面板拥有焦点时不拦截其按键。错误和自动下一项不夺焦点。自动推进可更新当前图标，但保留用户正在查看的选择。

隐藏只是 visibility 变化，不销毁组件、清空队列或暂停。再次显示不重新编译/重建组件。首次未知组件挂载允许遵守 B1 的“准备界面”及有限 shell 重建，须保存/恢复布局、选择、滚动和焦点，不重启播放 backend/session/插件实例。可行性评估推荐宿主以标准Slint import组合非Window侧栏组件，并用包实例独立global桥接呈现属性/回调；真实model/struct桥接待共同基线，不读其他包global，不能称外窗已满足侧栏。

停用/崩溃由宿主移除本实例组件、命令、选择器及订阅；插件撤销自己的本地异步工作，令迟到结果无效。该动作不关闭当前媒体、不重置其他组件；已提交打开请求可能已改变公共来源，不能伪称停用会回滚。

## 4. 状态、连续交互与失败

### 4.1 队列、去重和编辑

每行有插件生成的稳定 `rowId`，文件定位、去重 key、显示名和最近一次加载错误；绝不以可变行号关联异步结果。来源路径取自系统选择器，仅接收本地文件。对可解析文件使用 Node `realpath` 的规范路径作为去重 key（保留大小写，不主动 lowercase）；硬链接不同路径视为不同项，不按文件名/大小/内容 hash 合并。对不存在、不可读或无法解析的路径保留规范化绝对路径 key 和局部失败原因，不静默丢弃；以后重试能解析时重新核对 key，若与另一行冲突则选中已存在行并解释，不保留重复项。文件系统的同一真实目标可通过 realpath 合并，不能声称完成全文件系统身份去重。

同批与已存在 key 都去重，保留首次出现顺序；不对文件类型预断定成功，真实可播放性由公共解码结果确认。系统选择器返回顺序作为插入顺序。确认后给出“新增N项，跳过M个重复，K项待重试/无效”的简短摘要。空列表选中首新增项；已有队列保持选择、当前项和播放。添加不调用 open，无媒体时也不自动播放。

上移/下移只改变顺序，保留 `rowId` 与选中项。自然推进使用提交推进时的现有顺序，不缓存已过时的 index。移除选择后选中原位置的后继，否则前驱；清空则无选择。删除非当前项不影响受控 session。删除当前/正在打开项时保留已经播放或接受的公共来源，显示“当前媒体已移出列表”；撤销队列控制权及自动推进资格。清空同理，不调用关闭来源。行内加载结果在行已移除后不得重建该行。

### 4.2 选择与播放所有权

本地持有 `queueRevision`、`intentEpoch`、`selectedRowId`，以及可空的受控绑定 `{rowId, session, openCorrelation, epoch}` 和最近显式打开失败的 `failedTargetRowId` 导航锚。队列不是全局播放器所有权；该绑定只表示本插件确实发起且仍认可的这一次普通媒体打开。相同文件被其他入口重新打开也必须有不同 session，绝不能用 source 字符串相同当作本插件会话。

播放选中项、上一项、下一项创建新的显式意图，失效旧绑定及旧推进任务，标记目标“正在打开”。上一/下一以仍在队列的当前受控行或最近一次显式打开的失败目标行为锚；失败目标优先于此前媒体/选择，不能因加载失败撤销受控绑定就退回选择。单击选择其他行不改变失败锚，例如B失败后选择D再按下一项仍打开C。删除失败目标/清空队列才撤销该失败锚；成功接受新的显式列表打开或更新的外部来源意图结束旧失败导航上下文，新打开结果重新确定当前/失败目标。无受控行且无失败目标时才以选中行为锚；无锚或边界则禁用，不循环。显式播放失败行是重试；下一项也允许用户主动绕过失败行。加载中暂停和取消语义不由列表猜测：本插件本次打开接受/未知期间禁重复打开 action，队列编辑与其他插件的公开操作仍可用。

open 接受仅获得来源身份，不代表播放成功。只在结构化 ready 且匹配关联/session 后显示已就绪；pause 从公开状态投影，不能自己假定新项必为播放。媒体打开是否自动播放须由共同来源契约明确；本列表期望显式“播放”产生未暂停的普通媒体，并请求 maintainer 将这一语义纳入统一打开动作，而非在迟到 open 回包后对不明当前来源裸 `set(pause,false)`。

加载失败停在目标行，保留独立于选择的失败导航锚、路径、原因及重试/下一项入口，不自动跳过或循环重试。不把旧媒体最后一个 position/duration 显示为新行状态。未接受请求的失败不制造新 session；接受后失败以该 session 的结构化 error 确认。

### 4.3 自然结束、外部切源及竞态

只处理绑定仍有效、实际事件 session 匹配、终因明确是自然结束的终止事件。replaced、用户关闭、加载错误、插件停用、外部 NES 等来源切换不推进。自然结束一次后标记已处理，重复事件不得双开。末项标记“列表已播完”，不循环、不自行关闭来源，公共终态应停止继续播放。

有后继时在插件串行 action 队列中重新验证 row 存在、当前顺序、epoch 与受控 session，产生自动下一项请求。这个本地检查不足以阻止检查后发生的手动切源，因此请求公共宿主提供原子条件打开或等价事务：只有被结束 session 仍是公共来源的最新选择身份时才能提交新打开；即便自然结束已清空画布，也需有可比较的最后来源 generation。手动打开/关闭/切NES先胜出时自动请求以 stale/conflict 被拒绝，不覆盖用户新来源。公共设施只比较来源身份/公开控制意图版本，不持有队列/下一项策略。

用户在 ended 来源上显式“从头再播放”也是新的公开来源控制意图。即使实现保留同一 session，公共 generation/version 或等价条件身份也必须变化，使基于旧 natural-end 的待执行自动推进原子失败；仅比较路径或不变 session 不足以保证这一点。列表观察公开新意图后失效旧推进 epoch，不读取或直连基础播放插件。重播的来源仍可保留其队列行关联，但旧结束事件已消费；只有新一次播放对应的自然结束资格才能再次推进。具体 restart、身份更新及重新关联语义由 maintainer 在共同契约确定，示意字段不冻结签名。

打开回包与来源事件可能交错，需通过公开调用关联及单调事件顺序/可查询快照恢复：先建立请求关联，归集匹配 lifecycle，再绑定回包 session；任何接受事件后已观察到更新的外部来源意图，不得因迟到回包重新授予绑定。不得把约100ms旧 `playback.state` 或 backend `currentSession` 当来源证据。若共同契约不能提供原子比较和事件来源身份，自动推进是必要 API 阻塞项，不能退化为解析 mpv Debug。

外部手动打开即撤销当前受控绑定，行可显示“已切换到列表外来源”，保留队列/选择。即使新 source 路径刚好相同也不接管。手动操作后仍可显式选播/上一/下一重新进入队列。隐藏侧栏不改变 epoch 或绑定。

### 4.4 取消、结果未知与重复输入

文件面板取消是单独结果，队列、选择、会话全不变；选择器错误显示局部原因。重复点击添加只保留一个请求，按钮与菜单同步忙碌。停用时取消归本实例的面板，迟到确认不能追加到新实例。路径规范化在插件侧异步完成，以批次/实例 epoch 隔离，期间仍可播放现有媒体，不阻塞 UI。

瞬时 open 一旦接受没有回滚取消。本插件不添加假“取消播放请求”按钮；timeout显示“打开结果未知”，禁止盲目重试，使用公开关联查询恢复实际状态，其他队列编辑仍可用。明确错误可重试；若发现更新的外部来源，放弃该旧请求的队列控制权。禁用插件取消本地处理不等于取消已经提交的来源改变。不会用 error 自动下一项，也不会把 timeout 显示为已取消。

## 5. 公共 API usage 与缺口

### 5.1 初版已有与不能假定已有

初版已有 `capabilities()`、`playback.open(path)`（仅接受返回session）、`playback.state()`、`playback.set`、事件订阅与独立 `ui.window`。它们支持能力诊断和读取基础状态，但不足以完成本方案侧栏、列表、文件面板或可靠自动推进。下例只是已实现 API 的语义展示，不是完整插件实现：

```ts
const accepted = await host.playback.open(absolutePath);
// accepted.session 不是 ready，也不是该行已开始呈现的证明。
const state = await host.playback.state();
// state 可能是旧快照；不能据此向下一项自动推进。
```

### 5.2 请求扩展：语义 usage，名称/签名未冻结

```ts
// PROPOSED ONLY：与 maintainer 合并 B-01/02/03/04 后确定公开签名。
const panel = await proposed.mountSlint({
  slot: "sidebar", component: "playlist.slint", preferredWidth: 280,
  minWidth: 240, rows: queueView, // stable rowId + primitive row fields
});
const picked = await proposed.pickLocalFiles({ multiple: true });
if (picked.kind === "selected") await addAndDeduplicate(picked.paths);
// natural-end handler only; queue policy and target selection stay in plugin.
const opened = await proposed.openOrdinaryMedia({
  path: next.path, correlation: localIntent,
  startPaused: false, expectedSourceCondition: ended.publicCondition,

// A later manual open/close/restart changes publicCondition: stale auto-next rejects.
// Actual ready/error carries opened.session and correlation; compare before UI apply.
```

示例中的 `proposed`、辅助函数和字段均为讨论用法，不属于0.1且不能编译当SDK样例。Slint实际使用原生布局、ListView/model与导出 callback，宿主仅桥接确定类型的数据，不建JSON布局系统。模型更新须有稳定ID和修订/有序投递语义，点击旧行快照须在插件验证 rowId 存在，不按index误播。
