# 音频工作台方案 C2

日期：2026-10-17。状态：有限完整设计草稿，待交互负责人/API maintainer 集中审查。对应全局 B1（[product-interaction](../product-interaction.md)、[menu-map](../menu-map.md)），当前 SDK `vestra.experimental/0.1`。本文不发布 API、不实现产品、不宣称测试通过；共同基线及 root 实现任务下达前不得开始实现。

## 1. 职责与使用场景

在真实视频连续播放时调节五段均衡器、声音相对画面的偏移、动态规范化和高频清晰度增强；提供平直、人声两个预设以及仅撤销本插件调节的复位。音量、静音、播放/暂停、seek 属于基础播放；工作台不复制这些状态或控件。独立运行只需要公共播放/处理设施及测试宿主，其他七个产品插件均可不存在。

TS 负责参数校验、预设、合并连续输入、窗口与状态策略；Slint 负责原生界面；Rust 公共设施通过成熟 libmpv/FFmpeg libavfilter 安全接口处理声音及时间戳，不自写 DSP，不向 TS 常规传送 PCM。第一方 Rust 禁止 unsafe。不提供任意滤镜字符串、通用插件混音图、声道编辑、专业 DAW、录音或频谱仪。

### 有限参数与算法

| 项目 | 确定范围/默认值 | 处理定义 |
| --- | --- | --- |
| EQ 五段 | 100、300、1000、3000、10000 Hz；每段 −6..+6 dB，步长0.5；默认全0 | FFmpeg `equalizer` 峰值滤波，每段 Q=1（`width_type=q,width=1`）；各声道相同设置，不改变声道布局 |
| 同步偏移 | −2000..+2000 ms，步长10；默认0，数值输入须为有限10ms整数倍 | +值表示声音晚于原始画面，−值表示声音提前；0清除本插件的用户偏移，不关闭宿主正常 A/V 同步或算法延迟补偿。写给底层时转换秒；不做seek |
| 规范化开关 | 默认关闭 | FFmpeg `dynaudnorm`，在线动态响度平整，不宣称 EBU R128/LUFS 达标或两遍分析 |
| 规范化设置 | 最大增益1..4倍、步长0.1，默认2；目标峰值0.50..0.95，步长0.01，默认0.90 | 固定 frame length=100ms、gaussian window=5、channel coupling=true、correct DC=false、compress=0；其余选项固定所选后端版本默认并在共同基线记录。动态历史由后端保留，seek/换源按后端明确重建 |
| 增强开关 | 默认关闭；文案“高频清晰度” | FFmpeg `treble` 双极高架滤波，中心3000Hz、宽度类型 slope、宽度0.5；增强不是降噪/分离人声 |
| 增强强度 | 0..6 dB，步长0.5，默认2 | 开启时以上述高架增益处理；0dB为中性，但开关仍可明确显示开启 |
| 内部电平保护 | 无单独用户入口 | EQ/增强之前固定补偿 `−(五段正增益之和 + 已开启增强的正增益)` dB，使用成熟 `volume` 处理；全中性时为0。防止级联增益导致削波，不改公共播放音量或静音 |

处理顺序固定：本插件电平补偿→五段EQ（由低到高）→增强→规范化→宿主输出电平/设备。禁用的效果旁路；全平直且偏移0时撤除本插件的非必要处理节点。跨owner链顺序由宿主公开稳定排序决定，本插件不能清空全局 `af`；规范化可能改变其他owner先前处理后的动态，需在诊断显示实际顺序。

算法依据：[FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html) 的 equalizer、treble、dynaudnorm、volume；实际运行版本/编译可用滤镜要由能力协商检查。[mpv 手册](https://mpv.io/manual/stable/) 说明音频滤镜与延迟控制。这里的有限值、预设与保护策略是本插件的产品选择，实时重配置、延迟补偿和无间断效果仍必须实测，官方文档不构成本轮通过证据。

规范化有前瞻/平滑缓存，公共设施须报告可观测处理延迟或明确unknown并提供测量证据，依成熟后端同步设施维护 A/V 同步；不强制反射内部DSP状态；用户偏移与这项补偿分开。不得用猜测的固定250ms当作正确补偿，也不得通过重开媒体解决重配置。若成熟后端尚无法达成连续性，登记阻塞交 maintainer，不静默换算法。

| 预设 | EQ 100/300/1000/3000/10000Hz，dB | 规范化 | 增强 | 用户偏移 |
| --- | --- | --- | --- | --- |
| 平直 | 0/0/0/0/0 | 关闭；最大增益2、峰值0.90 | 关闭；强度2dB | 0ms |
| 人声 | −2/−1/+2/+3/0 | 开启；最大增益2、峰值0.90 | 开启；强度2dB | 0ms |

两预设一次原子更新完整配置；预设包含偏移，因此切换前界面文字明确“包含同步偏移”。复位等于恢复平直表格全部值并撤自身有效效果，不触及任何owner的音量、静音、速率、字幕或视频。预设单选以完整确认配置匹配，任何值不同显示“自定义”；未生效的草稿不能让菜单先行勾选。

## 2. 入口与命令表

命令ID是插件内部动作标识，不是已批准路由API。所有菜单与按钮调用同一action。无全局快捷键；键盘可按Tab到达全部控件，数值框Enter提交，Escape先撤未提交编辑/弹层，再隐藏窗口。

| 功能/命令 | 唯一主菜单路径 | 按钮/其他入口 | 直接执行或打开界面 | 启用条件 | 权威状态来源 |
| --- | --- | --- | --- | --- | --- |
| `audio.eq` | 音频→均衡器… | 五段滑条/数值框 | 显示唯一工作台并聚焦EQ首段 | 插件运行，UI可用 | 已确认resource配置；无源为本地待用配置 |
| `audio.delay` | 音频→同步偏移… | 偏移滑条/数值框、“归零”按钮 | 同窗同步区；归零只改偏移 | 同上；不支持音频处理的当前源只允许编辑待用值 | resource偏移与applied session |
| `audio.normalization.toggle` | 音频→规范化→启用 | 同区开关 | 立即切换 | 公共处理能力支持或无源编辑 | 后端确认开关 |
| `audio.normalization.settings` | 音频→规范化→设置… | 最大增益/目标峰值框与滑条 | 同窗规范化区 | UI可用，关闭状态也可编辑待用参数 | 确认参数/草稿分离 |
| `audio.enhance.toggle` | 音频→增强→启用 | 同区开关 | 立即切换 | 同规范化 | 后端确认开关 |
| `audio.enhance.settings` | 音频→增强→设置… | 强度滑条/数值框 | 同窗增强区 | UI可用 | 确认参数/草稿分离 |
| `audio.preset.flat` | 音频→音频预设→平直 | 平直按钮 | 原子应用表格值 | 支持处理或无源编辑 | 完整确认配置 |
| `audio.preset.voice` | 音频→音频预设→人声 | 人声按钮 | 同上 | 同上 | 完整确认配置 |
| `audio.reset` | 音频→复位音频工作台 | 复位按钮 | 立即复位本owner配置 | 有修改/待用配置时 | owner资源确认/撤除结果 |

右键投影上述同一音频菜单，必须逐条验证可达；不另开工具菜单。基础播放的静音/音量仍在音频领域，由其拥有。当前来源（如未声明音频处理支持的NES）不支持时，应用动作禁用并说明“当前来源不支持，参数保留供普通媒体使用”；窗口入口仍可用。后端缺滤镜时相关开关/人声预设禁用并给出具体缺能力；不能假装完整预设已生效。无媒体菜单选择编辑下次配置，提示“下次支持的来源使用”；这不是当前声音已处理。

## 3. 界面与生命周期

独立、非模态 Slint Window，初始560×520，最小440×360，控件区垂直滚动，底部状态/复位保持可达。激活只准备资源/组件，不自动显示、置顶或抢焦点；按B1首次准备规则可显示进度，日常显隐不重编译。

```text
音频工作台                       系统关闭(隐藏)
当前来源 / 已应用session / 预设:自定义
[平直] [人声]   包含同步偏移
均衡器：100 300 1k 3k 10k Hz
         五段滑条与dB数值框
同步偏移： [−2000 … 0 … +2000] [ms框] [归零]
           正数声音更晚，负数声音更早
规范化：[启用] 最大增益[2.0x] 目标峰值[0.90]
增强(高频清晰度)：[启用] 强度[2.0dB]
────────────────────────────────────
状态：待提交/应用中/已确认revision/错误    [复位]
```

入口显示后滚动到对应区并聚焦其首个可编辑控件；已显示只聚焦，不重建。用户在数值编辑时方向键/Space归编辑器，不触发播放；后台确认、换源、错误仅更新状态不移动焦点。关闭后恢复来源窗口仍存在的控件，实际输入由通用焦点设施管理。

主播放画布与常驻栏持续存在，工作台不占它们的挂载位置。窗口关闭/Escape只是hide，效果及已提交请求继续，显示后恢复草稿/确认值；destroy UI也不撤处理。停用/崩溃由宿主撤本实例处理资源、延迟贡献、订阅、命令、窗口，不能依赖TS dispose成功；不改播放pause、位置、source、音量/静音，不撤其他owner效果。重启插件取得新generation，默认平直，不接收旧ack；持久化用户参数不在本轮范围。

## 4. 状态、连续交互与失败

分别保存 `draft`（用户输入）、`desiredRevision`、`confirmed`（宿主接受的完整配置/revision）、`applied`（具体session已应用/等待/不支持）、owner generation。确认不是PCM已经输出；UI“已应用”须有后端应用事实，否则写“已接受，等待应用”。输入不合法（NaN、越界、非步长）就地说明，Enter前不发送，不默默改变现有链。

- **无媒体/无音轨**：窗口可编辑配置；无媒体只存待用值，不调用裸set；媒体无音轨显示无可处理音轨。支持音轨出现时按新session/track条件原子应用完整最新配置，不能先对旧会话写再补救。
- **加载/换源**：停止旧session拖动发送，丢弃旧pending；新源就绪且声明支持时重新建立/重绑定本owner资源并提交最新完整配置。换源事件及提交的session CAS由宿主保证；UI显示加载中/待应用，不使用mpv Debug事件推断。旧session ack只能进入旧诊断，不能改当前确认状态。
- **暂停**：可调参，保持paused与position；处理配置可确认，直到恢复输出后才有听觉证据。seek/暂停不引发插件主动open；动态算法历史重置属于宿主明确后端事实，不改变用户参数。
- **连续拖动**：UI立即显示草稿；约33ms窗口内只保留最后完整配置，最多一个在途提交和一个最新pending，队列长度常数。释放后必须最终提交最终值，若在途则置release-final pending，收到确认后立即发送；新拖动/预设/复位递增revision，过时ack不覆盖新草稿。每次滑条不重建播放会话/重启视频/暂停/seek，亦不可每次参数事件重建全部音频图和清空动态历史。后端需支持成熟滤镜运行时命令或其他满足连续性的公开更新路径。
- **重复操作/预设**：切换、预设、复位是完整desired state替换；正在提交时后续动作合并为最新完整状态，允许最后一次操作生效。窗口底部显示待提交/应用中；菜单勾选保留最后确认值直到确认。无独立“应用”按钮，松手/Enter是提交点。
- **失败**：invalid/backend/unsupported均显示具体局部错误；原子失败留最近有效链，当前revision无新草稿时UI恢复确认值；有更新草稿则不擦除，标明未应用并可重试该控件动作。timeout为结果未知，暂停继续发新请求，先以request token查询实际状态，恢复前不显示复位成功。disabled结束发送，清理计时器，不重试已停用owner。stale-session拒绝后只对新session重新验证，不原样重放旧请求。
- **取消**：数值框Escape只撤未提交草稿；已提交即时参数没有回滚式取消。隐藏窗口不取消最终提交。复位是明确的新配置更新。音频插件不启动长任务、不请求系统文件选择。

导出等任务通过公共设施捕获“已确认且已实际应用”的不可变音频配置、算法版本、链顺序、用户偏移及有效source/session/track。草稿/pending不进入快照；如存在结果未知，获取快照应拒绝或等待明确结果，不能默默取未确认值。任务持有独立快照生命期；关窗/调参/换源/停用/崩溃不改已创建任务输入。音频插件不能调用导出插件；实时owner撤除也不撤任务的不可变快照。与R2/B1统一：processed MP4包含上述确认已应用音频链、顺序、算法版本与用户偏移，不烘焙设备volume/mute；raw MP4使用选定源音轨。动态规范化按固定原源preroll重算，按maintainer P1以源起点0到导出起点的实际范围作为preroll，处理后裁取目标范围并重置输出PTS；记录实际范围、track、算法版本、端点及延迟规则，提示准备可能较长。偏移所需边界采样按公共规则补零/裁切并保持目标时长，后续缩短preroll必须另有误差边界与发布记录。不克隆内部DSP状态，不承诺与实时输出逐样本相同。参数和预热边界共同进入任务快照。

## 5. 公共 API usage 与缺口

**初版已有且可运行的消费形式**（仅示意基础能力，不作为本方案效果实现）：

```ts
const state = await host.playback.state();
const off = await host.events.subscribe("playback.state", onState);
await host.ui.open("audio", "audio.slint", { status: "待用参数" }, ["adjust", "released"]);
await host.ui.show("audio", false); // hide保留效果
// host.playback.set("audio-delay", 0.1) 初版确实存在，
// 但无owner、读取/撤销/CAS，产品不能使用它模拟本方案处理资源。
```

**请求扩展，以下为不可运行的usage草案，不是SDK签名**：

```ts
const resource = await proposed.audio.create({ order: "stable-public-order" });
const receipt = await resource.replace({
  expectedSession: ready.session, expectedTrack: ready.audioTrack,
  revision: ++revision, requestToken,
  effects: finiteValidatedNodes(config), userDelayMs: config.delayMs
});
// receipt: owner generation/resource revision/accepted；另有applied事实
const confirmed = await resource.read();
const outcome = await proposed.requests.lookup(requestToken); // timeout后查询
const snapshot = await proposed.media.snapshot({
  expectedSession: ready.session, audio: "confirmed-applied",
  dynamicHistory: "recompute-source-zero-to-export-start", // P1确定性重算后裁取
  outputAudio: "processed-chain-and-user-delay-excluding-device-volume-mute"
}); // 由请求任务方使用；音频插件不会调用其他插件
```

Slint继续用标准布局/widgets，primitive桥接足以承载五个固定数值；`adjust(index,value)`与`released(index,value)`仅是希望的callback签名，不是已经存在的手势/控件能力。

| 请求 / 关联 | 所有者、输入输出与清理 | 错误/取消与最小观察场景 | 状态 |
| --- | --- | --- | --- |
| AU-01 / B-05 通用音频处理resource | 实例generation拥有句柄，输入有限已校验公共处理节点及完整revision；输出确认配置、链顺序、backend算法版本/可用性、applied状态；宿主提供稳定跨owner顺序，停用/崩溃撤自身 | replace原子成功或留旧链；unsupported/backend明确，timeout可查询；EQ+规范化+增强同时生效，另一个owner保留处理，停用只撤一个owner；拖5秒无重load、无积压/断音画 | 请求扩展；发送maintainer，非批准 |
| AU-02 / PB-04、B-05 资源化偏移/会话条件 | 延迟同resource，ms语义明确；session/track原子校验，0撤本贡献；多个owner延迟按公开规则合成并可读（建议加总且范围越界原子拒绝）；算法固有延迟另行补偿/报告 | stale-session不写新源；owner卸载只撤本项，保留基础同步和他方偏移；±500/0ms真实闪光+脉冲验证，不只读参数值 | 请求扩展，最终合成规则待maintainer |
| AU-03 / B-07 不可变处理快照 | 任务请求方持有与实时owner分离的snapshot，绑定source/session/track、已应用revision、链序、算法版本与用户偏移；processed包含该音频链和偏移、排除设备volume/mute，raw使用选定源轨；动态规范化从原源0到导出起点作preroll重算后裁取，记录实际边界，不克隆内部DSP状态；任务释放后回收，不发PCM到TS | 无法固定输入/结果未知则拒绝创建；切源/停用不改已有任务；固定原源范围产生可检查音频，不要求与实时逐样本相同；不要求音频作者实现导出 | 请求扩展；R2统一边界已同步，按maintainer P1源0至导出起点preroll，待共同基线发布 |
| AU-04 / B-02、B-10 命令/窗口/输入 | 通用命令同一状态，分区聚焦、close hide通知、焦点恢复及release事件；实例退出撤全部UI和命令 | UI unavailable明确，不注册假可执行界面；实际菜单逐项、数值键盘、拖动释放及关窗后声音继续 | 请求扩展，复用全局请求不自造UI框架 |

## 6. 验收场景
