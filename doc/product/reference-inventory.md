# 参考播放器功能清单：用于插件实验选材

整理日期：2026-10-17。研究对象固定为 **reference player 260819，Windows x64 发行包**；主 DLL 文件版本为 **1.7.23122.0**。本文先完成清单，不选定实验插件，不改变现有 core API 或插件格式。

## 1. 来源、方法和覆盖范围

本轮实际下载官方 CDN 安装包，验证哈希，静态解包；用 REA 检查 PE 资源目录，再解析主 DLL 的标准 MENU 模板，并用同包中英文语言文件关联菜单标签、快捷键、对话框和字符串表。没有运行 Windows 程序，没有全面反编译机器码。

- [固定版本安装包](https://example.invalid/reference)
- 安装包 SHA-256：`4b9833adf53b78c2149fe13dd67f2504bf39ee30b45c03f09e5f2c25e43f9cfe`，与当时读取的 [Scoop 清单](https://github.com/ScoopInstaller/Extras/blob/master/bucket/classic.json)一致。
- `reference64.dll` SHA-256：`157feac17a2d31a51202c76e3fb1823c632dbaea45f5fbd6c30520b7a1fad78d`。
- REA 主 DLL 证据：`ev_06d4f6459b8bdc86ea0ff21480188583c3d30865d91b882511679da9ba2b782d`，资源树覆盖 757 个资源、1,528 个目录条目；其中 10 个 MENU 模板。
- REA 安装包证据：`ev_b9eb8891b2c5ab1060858136ae996ee5ab28387482777f637f61aa1bdce900a1`，确认其安装器 PE 资源；产品菜单来自解包后的主 DLL，不能把安装器菜单当产品菜单。

| 本文整理功能单元 | 106 | 合并方向、预设及重复入口后的人工功能归纳 |

这 106 项是功能归纳的工作粒度，部分跨功能条目会复用同一证据，不表示 106 个互斥、可完全独立实现的功能。

886 条标签记录中有 4 条 DVD 子菜单空标签；另有 1 个模板节点没有对应本地化记录。均保留为占位，未擅自补成功能名。

**覆盖结论是“固定发行包的静态资源清单”，不是当前版本所有功能已经实测。** 动态轨道、设备、扩展和账号提供的项目，组合框完整取值、设置树层级、可用性条件、默认状态及精确行为仍可能需要 Windows 运行证据。资源中保留的广播等文字不能证明相关服务仍可用。

本次读取的官方包替代了前一轮版本未知的第三方语言文件；之前的 915 条计数不适用于这个版本。长于 240 字符的对话框说明和字符串表说明只保存摘要哈希，未复制整段帮助文本。未把原安装包、DLL 或完整语言文件放进仓库。

## 2. 如何使用这份清单

- **功能**：面向用户的操作或策略。同一功能可以有菜单、快捷键、设置和面板等多个入口。
- **候选功能组**：方便后续讨论插件归属的暂定标签，不是已选择的实验插件，也不要求每个标签单独成为插件；可以合并、拆分或最终归入核心设施。
- **core 议题**：由我们根据功能推导的问题，不是参考播放器内部架构的逆向结论。
- **证据键**：`M:` 是菜单路径，`D:对话框/控件` 是本地化文本，`S:` 是字符串表键。它们分别可在下列 JSON 检索，并附中英文原文、文件行号；菜单还带实际 CmdID 和 DLL 字节偏移。

阅读入口：

- [完整中英文静态菜单树](research/classic-260819/menu-tree.md)：浏览全部非分隔节点。
- [menus.json](research/classic-260819/menus.json)：模板节点、路径、标签、快捷键与命令映射。
- [commands.json](research/classic-260819/commands.json)：同一 CmdID 的多个菜单入口。
- [dialogs.json](research/classic-260819/dialogs.json)、[strings.json](research/classic-260819/strings.json)：菜单之外的设置与动态操作证据。
- [features.json](research/classic-260819/features.json)：本文 106 项结构化功能单元。
- [metadata.json](research/classic-260819/metadata.json)、[resource-map.json](research/classic-260819/resource-map.json)：来源哈希、统计和 REA 资源位置证据摘录。

菜单键不是命令 ID。例如 `101_0_9_0` 和 `115_0_0` 都映射到 CmdID `10014`（播放/暂停）；列表打开在 `101_0_9_9_1_0` 和 `111_0_4_0` 复用 CmdID `10000`。另一方面，两个“打开文件”入口的 ID 分别是 `10443` 和 `10158`，是否存在打开行为差异须运行核对。不能仅靠文字或 ID 断言功能完全相同。

表内快捷键是资源中所列的候选入口，最多展示四个；不是对当前用户配置或所有快捷键的保证。父菜单的子项快捷键请查看完整菜单树。英文和中文不一致时保留双方，不自动认定某一翻译正确。

## 4. 盘点中需要保留的区别

1. **功能分组不等于菜单结构。** 例如字幕的加载入口分布在“打开”和“字幕”，音频录制、视频录制与截图也可按任务能力重新组织。我们后续可以让一个插件贡献多个菜单入口。
2. **参数控制不等于算法在 TS 执行。** 色彩、音频 DSP 和 GPU 增强等面板负责设置，计算可以由成熟播放后端或原生提供者执行；具体桥接仍待实验。
3. **画面增强不等于 DLSS 5。** 这份资源明确出现 D3D11 GPU Super Resolution 与 RTX Video HDR，不把它们标成 DLSS 5。用户提出的 DLSS 5 是额外实验候选。
4. **白平衡尚未确认。** 此次中英文资源没有直接定位到白平衡/色温控制，不将其列为已发现的参考播放器功能；仍可作为我们的新增需求。画面色彩主题和视频色彩调节也不是一回事。
5. **后端/平台设置不必全部做成插件。** DXVA、设备、渲染器等菜单说明存在用户控制需求；底层资源生命周期和核心保障仍应由宿主/后端承担，插件只提供策略与入口是可能路线。
6. **资源存在不等于实现可用。** AI 模型下载、实时字幕、第三方滤镜、电视硬件与广播账号等依赖必须进一步核对。没有因此承诺 Vestra 支持相应平台、服务或 ABI。
7. **默认附带和可选扩展尚未划分。** 为完整发现需求，清单同时包含常用操作、平台高级控制与较特殊功能。NES、街机与 Pi 不是这份参考播放器清单的已发现功能。

## 5. 复现与校验

安装包只解包，不执行。下面命令需要 Python 3 和支持 NSIS 的 7zz；`extract_inventory.py` 会校验安装包、DLL 和每个使用到的资源 payload 哈希，拒绝把其他版本套入本次偏移映射。

```sh
curl -fL 'https://example.invalid/reference' -o /tmp/reference-setup.exe
7zz x /tmp/reference-setup.exe -o/tmp/classic-260819 'Language/*' 'reference64.dll'
python3 doc/product/research/classic-260819/extract_inventory.py /tmp/classic-260819 --installer /tmp/reference-setup.exe --output /tmp/classic-inventory
```

提取器按模板顺序和分隔符计算菜单路径，保留原始字段；CmdID 只在实际非 popup 命令中记录。`features.json` 的功能分组是人工整理，不由资源提取器猜测。

后续选择实验插件时，可据此比较不同功能组合需要的菜单贡献、状态、处理链、设备、后台任务与 UI 生命周期；本轮没有预选实验顺序，也没有改动已有实验实现。
