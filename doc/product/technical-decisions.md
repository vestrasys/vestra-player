# Vestra Player：技术选型

本文记录技术选择、职责边界和选择理由。项目原则见[项目方向](direction.md)，宿主内部结构见[架构总览](../architecture/README.md)，插件 API 见 [doc/plugins/](../plugins/README.md)。

## 1. 目标与约束

项目希望提供类似 PotPlayer 的丰富控制体验，同时允许用户组合和扩展功能。主要投入是交互、功能组织与插件生态；解码、同步、渲染尽量复用成熟基础设施。

选择必须服务于以下原则：

- **Everything is a plugin**：核心只保留运行和协作必需的基础设施，用户功能由插件提供。
- 官方插件与第三方插件使用同一套公开 API，不因官方身份访问宿主内部对象。
- 插件作者不需要理解 Rust 内部的类、窗口控制器或后端对象结构。
- 第一方 Rust 禁止 `unsafe`，原生能力通过安全封装或进程边界接入。
- 降低插件开发成本，允许写复杂、美观的原生界面；复用成熟 GUI 库，不自造 GUI 框架或布局语言。
- 默认插件组合成开箱即用的播放器，用户可以替换和扩展；插件商店不是架构成立的前提。

## 2. 技术组合

| 层 | 选择 | 职责 |
| --- | --- | --- |
| 宿主 | Rust | 播放后端接入、视频呈现、权威播放状态、界面组合、插件生命周期 |
| 界面 | Slint 1.16（slint-interpreter） | 原生窗口、控件、布局；插件的 `.slint` 在运行时由宿主编译，终端用户不需要 Rust 工具链 |
| 插件 | TypeScript，每插件一个 Node 进程（播放器内置 Node 26） | 用户功能、界面行为、命令与事件处理；可以使用 Node 标准库、网络、文件系统与 npm 依赖 |
| 插件 API | SDK v2（句柄式） | 插件看到的唯一 API；协议细节收在 SDK 内部 |
| 播放 | libmpv，经 rsmpv 安全封装 | 解码、同步、实时滤镜、字幕 |
| 导出 | FFmpeg 离线工作进程 | 截图、片段导出，独立解码，不影响播放 |
| 插件音视频流 | cpal 音频输出 + 有界帧队列 | 插件生成的画面与声音（如 NES） |

Slint 的 `.slint` 负责界面表达，TS 负责行为；两者之间只交换数据（属性值和回调），不传递函数或组件对象。

## 3. 为什么选择 Slint

宿主连接一个成熟的 GUI 库，让插件作者直接使用它的界面语言、布局、控件和样式，而不是重新设计一套控件 API。Slint 可以由 Rust 拥有原生窗口，插件行为留在 TS，不必让核心转向 Web UI，也不必自建 egui-to-TS 之类的包装。

React/Web UI、egui 包装等曾是候选，没有采用。这里没有对所有候选做同等实验，不把选择当作对其它框架的普遍结论。

接受的成本：插件作者要同时写 `.slint` 和 TS；跨语言的属性和回调连接由宿主与 SDK 适配（名称自动转换，与 Vue 的 props 规则相同）。

## 4. 核心与插件的职责边界

「播放功能由插件提供」指用户发起和操控播放的产品功能由插件组织，不是把解码器、播放时钟或窗口生命周期移出核心。

| 能力 | 归属 |
| --- | --- |
| 解码、播放时钟、音视频同步 | libmpv；宿主接入并提供能力 |
| 当前媒体、位置、暂停状态 | 宿主维护权威状态，插件订阅实际结果 |
| 播放窗口、视频呈现、界面重建时保持播放 | 宿主 |
| 打开文件、播放栏、播放列表、字幕管理等 | 插件（包括默认插件） |
| 滤镜执行 | libmpv / FFmpeg；插件只给出类型化的处理链，不逐帧处理像素 |
| 站点解析、下载策略、存档、预设 | 插件 |
| 跨会话持久化 | 尚未实现（宿主提供基础能力，策略归插件） |

插件不必让每次 I/O 都经过宿主：读文件、访问网络直接用 Node。宿主文件对话框只是便利服务。插件是受信任的，没有权限沙箱。

```ts
// 打开文件：插件的行为
const path = await plugin.dialogs.openFile({ title: "打开媒体" });
if (path) await plugin.player.open(path);

// 配置滤镜：插件给出处理链，播放后端执行
plugin.video.filter("blur").set([{ kind: "gblur", sigma: 3, steps: 3 }]);
```

## 5. 插件界面的接入方式

- **工具窗口**：插件的 `.slint` 由宿主在进程内用 interpreter 编译成独立窗口。编译不需要 Rust 编译器。
- **底栏 / 侧栏面板**：宿主把面板组件导入主界面再整体编译。首次挂载一个事先未知的面板需要重建主界面：播放后端、插件进程和已缓存的界面属性保留，播放不中断，但可能有短暂停顿或闪动。日常的显示/隐藏不重新编译。
- 隐藏的面板组件会被销毁，重新显示时重建：插件保存在 TS 里的状态会恢复，只存在于组件内部的状态（焦点、滚动位置）不会自动保留。
- Slint 的 `ComponentContainer` 动态嵌入接口仍在 interpreter 的 internal feature 下，暂不采用。

## 6. 尚待设计与验证

| 方向 | 现状 |
| --- | --- |
| 插件故障恢复 | 插件进程崩溃时宿主回收其资源，播放继续；自动重启与提示尚未设计 |
| 状态持久化 | 未实现 |
| API 版本策略 | 正式版本 `vestra/1`（由实验版本一次性切换，不兼容旧值）；不兼容的变更将以新的主版本发布，目前单一版本，未做多版本协商 |
| 插件管理界面 | 宿主有安装/回退能力，尚无面向用户的管理界面 |
| 硬件解码与 GPU 渲染路径 | 当前为 libmpv 软件渲染 |

技术方向已确定；具体能力按真实插件的需求演进（[社区工作流](../process/community-workflow.md)）。
