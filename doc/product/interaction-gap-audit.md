# 交互细粒度差异审计：Vestra 对照参考播放器

日期：2026-10-21。基线：main `89c78db`。

**方法**：按「状态 × 交互元素 × 行为」逐格对照，不只比较功能有没有。状态包括窗口模式、全屏、最大化、迷你尺寸/置顶、画中画、空闲（无视频）、纯音频。每一格写明参考播放器的规格及出处，Vestra 的现状及代码位置，并给出判定：**一致 / 差异 / 缺失 / 无法确定**。「差异（已裁决）」表示 [ui-alignment.md](ui-alignment.md) §1 或功能需求里已经有意选择偏离，这里只登记，不再提出整改。

**资料范围**

- 参考播放器：[research/classic-260819/ui/](research/classic-260819/ui/README.md) 的 A、B、C 三份报告，`config-defaults.txt`（下文写作「cfg:键名」），`dialogs.json`（写作「Dialog(n) 控件号」，附英文 ini 行号 `EN:n`），`strings.json`（写作「S:id」），`menu-tree.md`（写作「M:key」），以及 [classic-inventory.md](classic-inventory.md)、[ui-alignment.md](ui-alignment.md)（写作「UA §」）。
- Vestra：`src/host/src/*.rs`、`src/host/ui/*.slint`、`src/plugins/{playback,playlist,window,info,marks,hotkeys}`、[doc/plugins/reference.md](../plugins/reference.md)（写作「ref §」）、[menus.md](menus.md)。

**粒度说明**：参考播放器的证据全部来自静态逆向，没有运行过参考播放器。按出处分三档：皮肤或资源直接给出的写「确认」；由 SetDefaults 立即数或对话框文字推出的写「推断」；静态资料里没有的列入第 11 节，留待在 Windows 上实机观察。Vestra 的现状一律以代码为准，不以设计文档为准。

## 2. 窗口状态 × 界面元素

判定用的缩写：「布局」指占据窗口空间（会挤压视频）还是覆盖在视频上。

## 12. 逆向资料本身的缺口

这次逐格对照时，发现之前的规格提取在以下方面粒度不够，建议按右列的方法补充。

| # | 缺口 | 影响 | 建议怎么补充提取 |
| --- | --- | --- | --- |
| D-01 | **鼠标内置默认动作没有定位到**。C §4.2 只找到配置表全部为 0，没有找到「0 = 内置默认」时实际执行的代码 | 单击、双击、滚轮、侧键这些最高频的交互都缺少依据 | 反汇编鼠标消息处理（`WM_LBUTTONDBLCLK`、`WM_MOUSEWHEEL`、`WM_XBUTTONUP` 的分发函数），找出配置格为 0 时的分支，以及从 `0x1758` 偏移读取后的 `switch` 回退值；同时找 Dialog(458) 下拉框的填充函数（`CB_ADDSTRING` 的顺序与默认选中的索引） |
| D-02 | **自动隐藏相关的计时与区域常量没有找** | 全屏控制栏、指针、OSD 的时长都是「未知」 | 在 DLL 里找 `SetTimer` 的调用及其 nIDEvent 与毫秒立即数（例如 1000、2000、3000、5000），交叉引用到 `AutoHideMouse`（`0x53c`）、`PersistOsc`（`0x249c`）、`AttachOpenFullScreen`（`0x201f`）字段的读取；再找对 `GetCursorPos` 结果和屏幕边缘的比较（右边缘弹出的像素阈值） |
| D-03 | **只提取了 `VideoSkin.xml`，没有提取 `AudioSkin.xml`、`BottomAudio.txt`、OSC 的 Inside 层** | 纯音频状态和 OSC 模式无法对照 | 用同样的方法解析 `AudioSkin.xml`（布局、尺寸、时间字号）、`MainSkinAreaOscInside` 的子控件，以及其中可能存在的 `AutoHide`、`HideDelay`、`Animation` 一类属性 |
| D-04 | **皮肤属性的语义只是推测**：`VisMinLeft`、`VisParentMinWidth`、`AutoVisible`、`DownFlag`、`AltImage`、`IsSplitter` 等 | 窄窗口的按钮隐藏、按下态、分隔条的行为都只是推断 | 在 DLL 里定位皮肤解析器：属性名字符串的交叉引用 → 读取后存到哪个字段 → 布局函数如何使用。这样能得到确切的比较规则 |
| D-05 | **对话框选项只提取了标签文字，没有把每个复选框、下拉框和配置键一一对应** | 多数默认值只能由键名去猜测对应的标签（例如 `PauseOnLock=2`、`PlaybackFailSkip=0`） | 对每个首选项页，找它的 `DoDataExchange` 或 `OnInitDialog`：控件 ID → `CheckDlgButton` 或 `SendMessage(CB_SETCURSEL)` 用到的字段偏移 → `config-defaults.txt` 的键。产出一张「Dialog 控件 ↔ 配置键 ↔ 默认值」表 |
| D-06 | **加速键表只摘了一部分**（B §3.6 只列出相关的键，没有完整导出表 157/118，也没有确认 Esc） | Esc、Backspace 等键的行为无法确定 | 把 RT_ACCELERATOR 157 和 118 全部 259 + 54 条导出成 JSON（键、修饰键、CmdID、符号名），与 `command-symbols.json` 合并 |
| D-07 | **没有区分哪些命令有窗口状态的前置条件** | 全屏、迷你尺寸时各命令是否可用只能实机看 | 反汇编每条窗口命令的 `ON_UPDATE_COMMAND_UI` 处理（B §3.5 已有 340 条映射），把其中调用 `EnableMenuItem` 或 `CCmdUI::Enable(0)` 的条件整理成表（例如「全屏时禁用」） |
| D-08 | **OSD 的消息时长、队列和位置的取值**：`MessageHoriPos/VertPos` 的取值含义、是否自动缩放字号 | O-02、O-03、O-05 | 找 OSD 绘制函数里对这些字段的读取，以及计算字号的公式（是否按视频高度的比例） |
| D-09 | **列表行为的键只摘了默认值**：`DisplayAsThumbnail=1` 的含义、`SortModePL` 等 | L-13、L-14 | 找列表绘制函数：行高怎样由字号计算（`sPlayListFontSize` → `tmHeight` + 间距），选中与焦点框的绘制顺序，列的宽度 |
| D-10 | **字符串表里与状态有关的文案没有系统地归类** | OSD 文案里隐含的状态规则（如 S:1663「全屏/还原」、S:1674「播放列表 显示/隐藏」）没有用来推出行为 | 按「状态切换」类的字符串（`%s : On/Off`、`Restore`、`Show/Hide`）建一张索引，和 CmdID 对应，作为切换语义的证据 |
